# M1-05 / M1-09 implementation evidence

Date: 2026-09-16  
Status: in-progress

## Task card

- Requirements: NAV-001, NAV-002, NAV-003, NAV-006, CLI-001.
- Files: `crates/browser-core/src/navigation.rs`,
  `crates/browser-core/src/reducer.rs`, and the Qt URL-fact adapter.
- Observable result: navigation input is resolved deterministically without
  network probes; browser-supported URLs produce navigation effects; external
  desktop URIs produce a bounded native confirmation prompt and only an
  explicit confirmation queues a system-handler action; and same-document URL
  changes update the current URL without replacing the document target.
- Qt navigation now supplies the validated effective configuration to the
  shared resolver, so configured search-engine names act as data-only
  keywords and the selected `navigation.default_search` template is used for
  ordinary search fallback across typed opens, clipboard opens, downloads,
  clean-link operations, and routed opens.
- CLI-forwarded routed opens and fresh-owner initial CLI URLs carry explicit
  trusted provenance; only that source enables bounded absolute/relative
  local-path resolution. Direct IPC, secondary-window, UI, keyboard, and
  userscript navigation remains untrusted and treats local-looking input as
  search data.
- Failed loads retain a sanitized requested URL, final URL, bounded engine
  detail, and a classified failure kind (DNS, network, TLS, HTTP, download,
  or unknown) in a native failure surface. No retry control is exposed from
  that surface.
- URL policy now passes through one bounded canonicalization module: HTTP(S)
  scheme/host casing, trailing DNS dots, IDN labels, IPv6 brackets, and
  default ports are normalized while escaped path/query/fragment bytes remain
  unchanged. Its canonical HTTP(S) origin is used by the Qt site-policy path.
- Exit criteria reached for this slice: locked workspace tests, formatting,
  clippy, and `cargo xtask check` pass; help, version, and temp-basedir runs
  are exercised below.

## Limitations

The external-URI confirmation and system-handler handoff are now wired for
interactive and clipboard navigation. Failure categorization and safe error
context are wired for the primary and secondary views, while renderer-failure
qualification, full typed CLI dispatch, redirect/POST history fixtures, and
broader engine error categories remain open requirements. Quickmark resolution
uses the latest bounded profile-library snapshot; a just-committed mark may
wait for the normal worker refresh before it becomes eligible for navigation.
Redirect fixture coverage remains. The Qt
URL-change callback now mirrors
same-document-style URL updates, and the Qt object forwards navigation facts to
its bridge-local reducer. Sharing this state with the process-level bootstrap
and routing effects through a typed engine adapter remain open.
