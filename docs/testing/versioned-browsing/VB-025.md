## Behavior implemented

The browser-owned modal exposes profile-scoped commit list, detail, structural diff, delete-preview, and restore-preview projections. List and diff rows are capped at the existing 100-item page limit before being attached to QML views. Unsupported categories are rendered as bounded plain text, and error messages, identifiers, scopes, and change labels use explicit plain-text rendering. Saved page bodies, form values, cookie identities/values, and archive contents are not exposed by the structural detail projection.

The panel preserves exact commit-ID validation before constructing commands, paginates list and diff requests, and exposes ordinary focusable action buttons. The metadata worker fetches one bounded lookahead row, so `hasNext` is exact even for a full final page; display payloads contain only the requested rows. When commits exist, initial dialog focus is placed on the list for immediate keyboard navigation; an empty first page explains how to create a structural snapshot, while an empty later page explains how to recover from an out-of-range page. It explicitly handles Space/Return/Enter on focused live-restore preview, cancel, and confirmation buttons so keyboard activation reaches the same bounded actions as mouse activation. Restore remains a review step followed by explicit confirmation to open current live pages in a new window; no current-window replacement is implied.

## Compact native keyboard continuation — 2026-10-02

A real 627 × 694 Ferric window exposed a layout failure: after keyboard-opening
restore review, its confirmation button was laid out beyond the right edge of
the dialog. The corresponding new compact-window QML regression failed with
`body=563`, restore column `width=1010`, and the button starting at `x=851` in a
627-pixel window. Constraining that restore-review column to its parent width
places both review buttons inside the dialog. The current focused QML panel
suite passes 17/17, including compact geometry and automatic focus movement
from list to details, from details to the safe Cancel control, and back to the
list after another list result. `cargo xtask check --locked --offline` passed
after these edits, with 153 QML passes, 5 environment-gated skips, and no QML
failures; the workspace Rust tests and other applicable gates completed.

The rebuilt native application was retested against a disposable normal
profile containing one exact structural commit. The saved page was an
`unsafe-navigation` placeholder, so the confirmation did not replay a network
URL. With the process-local Qt accessibility switch, the target window's
AT-SPI tree showed the list and later the restore confirmation. Compositor
keyboard events addressed only to that exact Ferric window exercised Return
on the list, Return on the details preview, Tab from the review's focused
Cancel control to the confirmation, and Return to open a second native window.
The source window stayed mapped with one tab; the new window also had one tab.
The visible confirmation's native bounds were `(354, 312, 235, 26)` inside the
627 × 694 dialog, rather than the earlier off-window x position. A subsequent
`commit-list` result restored focus to the visible saved-commits list.

This is native keyboard/focus evidence for the structural placeholder journey,
not qualification of multi-page safe-GET replay, committed sidecars, current-
window replacement, an independent screen-reader audit, or production archive,
cookie and WebRTC capabilities. Those restore/capability concerns remain under
VB-024 and later slices; they do not expand VB-025's keyboard UI acceptance.

The 2026-10-02 current-source continuation added an ambiguous short commit-ID
regression at both boundaries. The panel disables inspect/restore actions and
refuses to dispatch a command or start a preview for `commit:12345678`; the
application parser returns `ambiguous-reference` for that same prefix. The
focused panel suite passed 18/18 and the application case passed. The pure
structural planner's runtime-ID invariance and application manifest-diff
redaction cases passed, as did strict application Clippy, workspace formatting
and complete `cargo xtask check --locked --offline`. Together with the
previous compositor-keyboard native journey, this satisfies VB-025's explicit
criterion: a keyboard-only user can discover, inspect and restore a structural
commit without a graph UI.

## Privacy and remaining limits

Rows remain metadata-only. The QML cap is a display bound, not authorization; Rust/application projections continue to own profile scoping and pagination. The action controls are ordinary Qt Quick Buttons with accessible names; the targeted native keyboard path above is not a full assistive-technology review. Page archive viewing, live stash, cookie inheritance, and cookie write-back remain independently gated and are not enabled by this UI.
