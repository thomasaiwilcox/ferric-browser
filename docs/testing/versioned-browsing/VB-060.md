# VB-060 — Cross-owner line registry and exact switching

Status: in progress. The application and QML paths are implemented behind the same explicit test build feature as VB-059; production clean branching remains disabled. Final compositor-visible focus qualification is still open.

The parent application retains each published child branch's exact source window/tab and distinct native child profile owner/first tab. `switch` resolves a bounded name or canonical branch ID only within that visible-parent lineage. Core rejects duplicate case-folded branch names; the application also refuses ambiguous resolution and stale source/child records. A child supplied from a separate runtime with the same local `TabId` fails the owner check. Closing a branch removes its switch target.

The Qt bridge checks the live child application, native profile generation and first view again before QML uses the existing `show`/`raise`/`requestActivate` path. QML requires the exact registered parent UI/window or child host/profile/view lease, with no fallback to the primary owner. Switching never navigates, restores cookies, or reassigns a profile. The child command bar resolves through its original parent UI; parent CLI/IPC `switch` uses the typed application route. This remains scoped to VB-059's visible-parent, single-tab children; nested lines and window-scope groups are later slices.
