# VB-070 — Cookie backend contract and secret projections

Status: verified (backend contract; native complete snapshot remains unsupported)
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree atop the baseline
Affected requirements: `VERSION-005`, `VERSION-009`; invariants `VB-I06`, `VB-I07`, `VB-I12`, `VB-I17`

## Behaviour

`BrowserApplication` now has a typed, application-owned cookie backend contract. Identity, snapshot, read-back, write and exclusive-apply guarantees are independent, with exact `CookieScope` for any positive claim. The public Qt constructor advertises lossy identity, observed-only snapshot/read-back, individual asynchronous writes and no exclusive apply. It carries the exact engine fingerprint and bounded evidence IDs; it does not infer stronger guarantees from an ordinary-cookie fixture.

`CookieReadResult` stores bounded core `CookieSnapshot` records only in memory, with explicit observation scope, interval, unknown/complete coverage, a consistent-boundary claim and optional bounded revision token. The ordinary serializable projection contains only a fresh opaque handle, count and diagnostic change/admission indicators. Secret-bearing result and boundary `Debug` implementations redact cookie material and revision tokens; capability `Debug` also hides site scope. No cookie record, key or value gains an IPC or persistence serializer. The result can expose a consistent snapshot only after checking independently supplied engine fingerprint, exact requested scope, capability claims, backend identity version and dimensions, supported attributes, named boundary evidence, complete coverage and exact records. Unknown partition/host provenance, observed-only records and semantic attribute gaps are refused even if metadata claims a complete read.

This contract does not connect a native observer, create a production cookie snapshot, seed a branch, or apply a merge. The current Qt path cannot construct a positive qualified capability record through its public constructor. An empty observed map remains unknown, not a verified empty jar. The application model does not claim erasure of copies elsewhere in Qt, Chromium, swap or crash dumps.

## Privacy and qualification boundary

All test records use fixed synthetic names and values. The test verifies that serialized projection and `Debug` text omit those bytes, and that projection keys are a closed five-field set. Core record limits cap observations and total secret material; no normal-profile or external account was touched. A future positive backend must provide reviewed native evidence for identity, source boundary, read-back and mutation control; this slice does not change `capabilities.json` or production flags.

## Remaining boundary

Native observation plumbing, bounded queues, source completeness, real seed/read-back and controlled write-back belong to later slices. A pure synthetic qualified read demonstrates the type contract, not current Qt support. `VERSION-006` and `VERSION-008` remain blocked on a reviewed backend and native qualification.
