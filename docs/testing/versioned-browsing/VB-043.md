Status: verified for bounded single-page capture staging and asynchronous blob I/O; broader multi-page capture and release remain separate.

Affected requirement and invariant IDs: VERSION-001, VERSION-003, VERSION-009; VB-I04, VB-I10, VB-I12, VB-I14, VB-I15

## Behavior or investigation

- Added a separate, bounded file-only object worker. It uses one worker thread, a one-command queue, bounded completions, operation-scoped cancellation, and never opens or writes the SQLite metadata database.
- Page capture staging now reserves the archive and manifest ceiling (64 MiB + 8 MiB) in the profile metadata transaction before creating the exact per-operation staging file. A reservation is released on publication, abort, cancellation, expiry, or stale ownership; if file work is still active, abort waits for that correlated completion.
- The application coordinator maps the internal reservation and file-stage tickets back to the caller's original `StorageTicket`. Installation requires a completed stage and returns a validated immutable-object receipt; object installation does not publish a manifest or visible commit.
- Blob scanning and hashing are chunked and observe cancellation. Staging and object-install paths are profile-local, private, exact-operation paths; debug output redacts private state paths and content hashes.
- Metadata requests retain their independent completion correlation while bounded object I/O runs.

## Focused tests

- Same-kind object-worker admission/correlation, cancellation during chunked hashing, and disk-reservation exhaustion/release have focused Rust coverage.
- A deterministic concurrency regression now pauses the real file-only worker after its first chunk of a 4 MiB staged archive, requires a separate SQLite metadata query to complete while the archive scan is still in flight, then releases the scan and verifies exact installation. The pause is test-only; production worker behavior is unchanged. This establishes worker/connection separation, not a device-independent metadata latency bound under saturated I/O.
- The focused regression passed; the complete storage suite passed 163/163 tests, and strict storage Clippy passed on this source state.
- A later worker-handoff regression rejects publication of an already-installed archive object when the manifest declares a mismatched byte count. Explicit abort leaves no visible commit, and restart quarantines the private orphan while retaining the failed operation state. The focused test, current full storage suite (166/166), and strict storage Clippy passed. This covers validation failure at the worker handoff, not native capture or a crashed metadata process.

## Privacy and ownership review

- The metadata reservation is bound to the selected normal profile and exact operation ID before file staging. Private/ephemeral persistence remains rejected by the application authorization API.
- The file worker has no database handle, and failure or cancellation cannot create a visible commit. A late linked but unpublished object remains an orphan for recovery rather than being exposed as a commit. Capture installation and manifest publication are separately ticketed; the metadata transaction verifies the installed object before creating a visible commit.
- Archive bytes are sensitive user data; no sanitization or secrecy claim is made.

## Native UI responsiveness under archive-worker pause — 2026-10-04

The feature-gated object worker now has a one-shot, ten-second-bounded test
pause after the first archive-copy chunk. In a disposable production window,
the normal one-use collector and Qt MHTML save reach that pause. While the
file worker is still held, the Qt event loop processes events and the live
window answers two state probes for its unchanged source view. Only then does
the test resume the worker; a fresh durable-profile reopen finds the one
archive-plus-sidecar commit. The hook is absent from default builds and
self-cancels if its test controller fails to resume it.

Separately, the storage regression pauses a 4 MiB copy and requires an
independent metadata query to finish before the file worker is released.
Same-kind admission/correlation, cancellation during chunked hashing and
archive-plus-manifest reservation release are covered by the storage suite.
`cargo test -p ferric-browser-storage --locked --offline` passed 194/194;
the feature-enabled 4 MiB metadata-query regression also passed. `cargo
xtask test archive` passed all 28 native journeys. Strict feature-enabled
Clippy for storage, Qt and xtask, formatting, pack validation and checksums
also passed. These tests establish the
separate worker and UI response under bounded I/O, not a device-independent
latency bound or a production-release certificate.
