## Behavior

`VersionedCaptureManifest` is a separate, bounded schema-2 metadata format in `ferric-browser-storage::versioning`. It has its own explicit structural-projection conversion, encode, decode and validation path. Its 8 MiB byte limit, window/page limits and five-minute capture-interval limit are independent of schema-2 session recovery. Typed logical IDs, the owner profile UUID, selected-page membership, lineage references, safe URL descriptors, integer zoom/scroll positions, bounded strings, warning codes and typed object-role/hash/size references are checked before encoding or accepting stored bytes. The reader performs a non-writing schema-1-to-2 migration; schema 1 did not define archive-backend identity, so legacy archive references remain preserved but unavailable even if old bytes contain a schema-2 backend claim. Unknown fields, malformed JSON, unsupported older schemas and newer schemas fail closed; a newer schema is identified before unknown future fields are decoded.

Structural conversion copies only the safe logical window/page descriptors from the admitted projection. It does not infer or store a page body, cookie value, archive, sidecar, title or policy snapshot. Page and cookie fidelity are `not-requested` even if the source projection has observation counts; observation is not durable capture. Debug output redacts messages, context names, titles and replayable URLs.

No manifest writer, SQLite migration, object publication, restore operation or durability acknowledgment is introduced here. Those are later slices. The storage-engine guidance kept file-format admission distinct from the eventual fsync/publication protocol; a passing DTO test does not certify crash safety.
