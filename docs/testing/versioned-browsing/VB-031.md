## Behavior

`FerricVersioningViewHost` constructs a `WebEngineView` under its own QObject creation parent before displaying it in the ordinary tab stack. The host is tied to the exact `WebEngineProfile` object and original window. Its bounded registry records opaque retention IDs, exact view handles, original tab IDs, profile leases and original visual hosts. Retaining a view hides and reparents it to the host; duplicate ID/view/tab registration and wrong-profile registration are rejected. Explicit release destroys the exact handle and consumes the record once. Missing IDs do not create a replacement view.

The primary runtime now creates ordinary tab and fallback views through this owner. View-pool reconciliation removes registered retained views from ordinary visible counts and stale-view destruction, and refuses to manufacture a replacement if a retained tab still appears in the visible core projection. Ordinary close and transfer detach paths refuse to destroy a registered retained view. The host does not yet grant stash admission, freeze a page, change core tab membership, or keep its original window alive after a confirmed close; those are later slices.

## Ownership and remaining boundary

The fixture uses synthetic local content and off-record profiles; no production cookies, credentials or private data are logged or persisted. A JavaScript reference alone is not considered native ownership: the view's creation parent is the retaining component. The registry is capped at the core limit of 32 entries and checks exact profile object identity. Production stash remains disabled. VB-033 must connect admitted reducer events to this host and prove freeze acknowledgement; VB-034 must implement prepare/adopt/consume; VB-035 must keep the original host alive or resolve its close decision before any retained view can outlive a visible window.
