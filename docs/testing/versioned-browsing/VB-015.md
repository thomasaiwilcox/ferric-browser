## Behavior

`plan_cookie_merge` accepts three complete, consistent, lossless snapshots from the same backend identity version, scope, required key dimensions and supported-attribute contract. Cookie names and values, partition tokens and backend-specific identity dimensions remain raw bytes. The key distinguishes domain, path, host-only and partition identity; unknown host-only provenance or partition identity refuses the plan. Snapshot construction rejects duplicate keys, out-of-scope site cookies, missing/extra identity or attribute dimensions and resource-limit breaches. Unknown per-key observations or semantic attributes produce unavailable items without a proposed operation; globally incomplete, observed-only or lossy snapshots reject planning.

At one caller-injected evaluation time, expired records are treated as absent. The deterministic key-ordered decision rule is: child equals base → keep parent; parent equals base → propose child set/delete; parent equals child → converged; otherwise conflict. Equality compares opaque bytes and all modeled attributes, including exact expiration; it never combines token values or extends expiry. A proposed record is an exact clone of the child input. Absence reasons distinguish verified missing, observed deletion and expiry. The output is a comparison only, not authority to apply it: no clock read, native read/write, filesystem access or serialization is present in this module.
