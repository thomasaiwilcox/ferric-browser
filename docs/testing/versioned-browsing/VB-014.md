## Behavior

`project_structural_scope` materializes one previously admitted, single-window scope at exactly its captured application revision. The caller supplies stable logical window/page IDs and bounded observation evidence tied to each exact captured document target; runtime tab IDs are lookup keys only and never appear in the structural DTO. The projection preserves admitted page order, selected logical page, context reference, pinned/muted state and integer zoom hundredths. Scroll coordinates require finite nonnegative bounded values. A safe-GET proof is required before a canonical URL becomes replayable; otherwise the DTO holds a typed placeholder. The URL constructor is sealed, fragments are dropped, and obvious credential-bearing URL forms are rejected. Page and cookie capture coverage default to `Unknown`, never empty or complete.

`diff_structural` compares logical IDs, not URLs or runtime IDs, and reports window/page additions, removals, moves and order, selection, context, safe URL classification, pinned/muted/zoom/scroll and page/cookie coverage changes. Before/after availability states distinguish known, absent and unavailable/unknown cases. It validates the input shape, emits stable reason/category codes without URL values, and paginates output to at most 1,000 events. Same-URL pages with different logical IDs remain distinct. Snapshot contents are immutable values after projection; no filesystem, native callback or reducer effect is invoked here.

This is the pure structural input and comparison layer. It does not create a durable commit, infer GET safety from a URL alone, capture policy configuration, or enable restore. The later manifest/storage and policy slices own those boundaries.

## Privacy and ownership review

No live page body, form content, cookie value, runtime window/tab ID or document token enters a structural DTO or diff event. `Debug` redacts replayable URLs; diff JSON reports categories and availability rather than URL values. A trusted admission caller must supply logical identity and safe-GET proof. Core rejects stale revision and malformed numeric state, but application/native integration and privacy policy remain future work. Current production capability gates are unchanged.
