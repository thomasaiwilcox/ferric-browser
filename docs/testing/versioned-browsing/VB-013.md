## Behavior

The 21 initial Versioned Browsing commands are definitions in the existing `CommandRegistry`, not a second help/menu list. `VersioningCommand::from_parsed` consumes only tokens from the existing `parse_chain` lexer and returns a closed enum. It bounds messages, names, references, list limits and site hosts; rejects unknown/duplicate options, unsupported invocation counts, trailing operands and incompatible combinations; and keeps context capture unavailable until VB-028. A quoted message or name remains literal data, including shell-looking text. `--editable` requires `--pages`; merge preview requires `--cookies`; default branch creation retains the snapshot-inheritance requirement, while `--clean` has its own capability set.

The command and action registries expose static lower-bound capability metadata, while the typed command supplies option-sensitive requirements. Seven primary actions use the existing subject/verb registry identity, with new `commit`, `stash`, `branch` and `merge-plan` subjects. This resolves the proposal's provisional `browser.versioning.*` IDs to the established `browser.<subject>.<verb>` convention, for example `browser.commit.create` and `browser.merge-plan.preview`. Command help and completion discover these registry entries. A structured IPC codec maps fields to parsed tokens without re-lexing command text; the Qt action decoder fixes `merge-plan preview` to `cookies=true` and rejects a caller override.

No new reducer event, native effect, persistence write, cookie write or default keybinding was added. Dispatching these registered commands still returns `UnsupportedCommand` until the relevant implementation and production gates exist. In particular, query commands do not create snapshots.
