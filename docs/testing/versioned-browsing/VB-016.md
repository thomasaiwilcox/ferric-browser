## Behavior

The application now distinguishes sensitive merge, restore and drop operations from generic mutations. A preview can be prepared only while its exact admitted operation awaits consent and its purpose matches. It binds the captured scope/native profile lifetime, application configuration/security revision, operation ID and deadline. A random typed `plan:` ID expires no later than the operation deadline or the 60-second confirmation limit. The book is bounded to 17 pending previews. Merge choices are sorted, unique and limited to actual conflict items; a missing conflict choice or unavailable cookie item leaves the preview non-approvable.

The application retains the immutable secret-bearing `CookieMergePlan` or typed commit/branch target separately from the UI-facing preview. Routine IPC can serialize only `RedactedPreview` counts, risk and availability, never cookie names/values or the retained plan. The accepted native preview must match the stored presentation exactly. A one-time native-decision sink, intended only for the trusted native UI adapter, produces a non-serializable proof; the application exchanges it for a one-use permit after rechecking owner, exact operation/scope, configuration/security revision, choices and expiry. The bare operation ID can no longer advance application-owned sensitive consent. Consumption returns the original immutable payload and fails closed on replay, stale owner, changed policy or changed presentation. Cancellation, completion, profile close and replacement invalidate attached previews.

This slice does not present a dialog, connect the native decision sink to Qt, execute restore/drop/merge or enable a cookie backend. Until native wiring is qualified, there is no user-facing apply path. Later operation and native-integration slices must preserve this trusted-adapter boundary; no page or IPC boolean is accepted as consent.

## Privacy, qualification and remaining work

Plan payloads and permits are in memory, non-serializable and redacted in `Debug`; only the count/category DTO derives `Serialize`. The native sink is transferred once and must never be given to page, command or IPC handlers. This is an application protocol test, not a native click or cookie-write test. The general-cookie negative capability evidence and all production feature flags remain unchanged. VB-080–089 must attach exact parent/child backend evidence and perform re-read/stale checks before any conditional write-back; native integration and release qualification remain later slices.
