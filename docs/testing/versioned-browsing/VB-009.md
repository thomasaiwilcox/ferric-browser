## Behavior

Core keeps retention, representation, request-relative page/form coverage, consistency, identity and persistence as independent facts. Coverage built from unknown counts remains `unknown`; a known zero-sized request is `not-requested`, whereas zero of a positive request is `unavailable`. Captured counts above the request are rejected. Headline labels such as LIVE, ARCHIVED, STRUCTURAL and PARTIAL derive from those facts and do not imply completeness, durability or live retention from another dimension. A lost retained view may still have a durable archive fallback without becoming LIVE.

Ten typed primitive keys match the checked-in capability-gate vocabulary. Support needs a bounded scope and probe evidence; production qualification is a separate gate with distinct release evidence. Duplicate facts fail closed. A snapshot-branch requirement explicitly needs clean branching plus cookie identity, snapshot and seed/read-back support; it cannot silently degrade to a clean branch. None of these core facts enables a production feature or claims current Qt cookie support.

Twenty-seven stable versioning reason codes and fixed sensitive-category tags carry no raw URL, cookie, editable content or profile field. The IPC adapter maps them to the existing `PublicError`/`Response::failure` path. Partial and unknown merge outcomes have explicit public codes and conservative guidance, avoiding any claim that state was unchanged. Runtime conversion uses the same projection.
