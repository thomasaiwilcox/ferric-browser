## Behavior or investigation

- Only a correlated `DownloadCompleted` event for the exact public page-save request, with positive received bytes within the archive cap and a still-current captured owner/document, is sent to the file-only installer.
- After asynchronous sidecar collection and before accepting its output or claiming Qt's auto-starting Save Page request, the adapter revalidates that the same captured view still owns the logical tab and still displays the captured URL. It records `document-changed` or `native-view-lost` before any stale sidecar/archive can be accepted. At archive completion, a missing exact view is likewise `native-view-lost` rather than being mislabeled as document mutation.
- If the native save call itself throws, the adapter repeats that identity check and reports the actual document/view loss when present; only a still-current view's save-start failure is classified as `invalid-archive`.
- Cancelled, interrupted, other non-completed, empty, mismatched, stale, and timed-out/native-view-loss cases cancel the exact operation and discard its visible commit path. UI status copy distinguishes these failure outcomes without exposing page data.
- The file-only worker checks the staged file under bounded size limits, computes SHA-256, and installs an immutable profile-local object. The metadata worker later revalidates the object and publishes one atomic tab manifest referencing it. The interval is checked for clock order and bounded duration, and archive coverage is set only after the object receipt is returned.
- The page-capture operation now owns an exact stage ticket through object validation, acknowledges that ticket before entering `Publishing`, and only reports completion for the matching durable metadata callback. Publication gets a separate bounded callback window; its reservation is preserved through that exact result or the timeout, and cancellation/timeout after publication begins is represented as an unknown outcome rather than a clean cancellation.
- Published MHTML object references now record the fixed `qt-webengine-mhtml-v1` backend identifier. Legacy or unknown identifiers remain metadata but cannot be opened in the isolated viewer; runtime bytes alone do not select a parser/backend.
- The native adapter now supports a bounded two-tab window capture with either strict all-or-nothing policy or distinct, one-use partial-page consent. Each page has its own stage, exact Qt request, archive receipt and optional sidecar; one aggregate manifest publishes only after every page has an explicit result. Single-tab and strict failures still publish no partial commit. The production action remains gated pending the release matrix.

## Revalidate the captured document before native save — authored 2026-10-06; not run

Sidecar collection is asynchronous. Before this continuation, the callback
could accept collected sidecar evidence and claim a new native Save Page path
without first proving that the original view still owned the logical tab and
still showed the URL captured at operation start. Later completion validation
would reject a stale document, but it could still perform an unnecessary native
save; a destroyed view getter could also escape this boundary and leave the
operation waiting for the much longer native-save deadline.

The callback now checks the exact current tab view and captured URL before
accepting sidecar output or claiming the native save. A changed URL records
`document-changed`; a missing/replaced view, empty URL, or throwing getter
records `native-view-lost`. The page failure is passed through the existing
one-use partial-window policy and otherwise cancels the strict operation. The
same classification runs if Qt's `save()` call throws: only a still-current
view receives the `invalid-archive` reason. At terminal completion, a missing
or replaced exact view now maps to `native-view-lost`, distinct from a live
view's mutation evidence. The transient request-object match remains on the
QML capture owner and is not added to the strict serialized Rust facts DTO.
QML helper regressions cover these classifications,
while source-boundary regressions check the production ordering before
sidecar acceptance/save claim, save-start exception mapping, and terminal
failure routing. These authored checks remain unbuilt/unrun under the deferred
final verification; production archive capture remains disabled.
