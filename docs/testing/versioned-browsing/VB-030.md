# VB-030 — Pure retention leases and view ownership

Status: verified
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree atop the baseline
Affected requirements: `VERSION-002`, `VERSION-009`; invariants `VB-I02`, `VB-I03`, `VB-I10`, `VB-I11`, `VB-I16`

## Behavior

`VersioningState` now records a typed view membership (`Visible`, `Retained`, `Transferring`, `Closing`), observed lifecycle (`Active`, `Frozen`, `Discarded`, `Lost`), exact original native/profile/window/document owner, optional prepared restoration window, and separate logical profile/view lease counts. Preparation reserves one view identity without a lease. `AcquireRetained` is the single logical acknowledgement after a native host has acquired both physical leases; duplicate acquisition is rejected. Failed native preparation can release the unacquired record. Transfer preparation and adoption require the same native profile instance and exact destination window; cancellation returns to the retained owner. Release consumes the record once, and lost/discarded events clear the live lease counts while keeping a diagnosable record until explicit release.

All changes go through the existing core reducer. The pure `membership_for_tab` projection gives the future native pool a typed answer without storing Qt handles. Active or prepared retention blocks ordinary tab close, discard, move, transfer-out, branch close and branch failure; it is not just a tab-strip flag. A renderer-termination event or new-document navigation invalidates live retention for that tab instead of silently claiming the old heap survived. Loss remains distinct from a successful resume. Existing normal recovery snapshots are not written for versioning-only transitions.

This is domain ownership state, not the native retaining host. The native slice must prove actual QObject/profile lifetime and only send `AcquireRetained` after both physical leases are held; a core counter alone cannot keep a WebEngineView alive.

## Remaining boundary

No Qt view is retained yet, and a logical lease is not evidence of native ownership. VB-031 must provide the real owner component and reconcile native views by this projection; later stash slices own native admission, dirty-work disclosure, shutdown and renderer qualification. The VB-020 hash-dependency approval remains separate and does not block this core slice.
