## Core model

`ferric-browser-core::versioning::identity` defines eight distinct UUID v4 newtypes: commit, branch, stash, logical page, retained view, operation, profile instance and application owner. Their text form includes a kind prefix and canonical lower-case hyphenated v4 UUID. Parsing rejects another kind, noncanonical/overlong text, nil/non-v4 UUIDs and non-RFC variants. Equality/hash/order are typed. `LogicalPageId` is a conceptual page slot; it is not the existing runtime `TabId`. `ProfileInstanceId` and `ApplicationOwnerId` are random lifetime identities, not durable authority after restart. `uuid` was already locked for other workspace crates; adding it to core changed only the core dependency entry in `Cargo.lock`.

`versioning::limits` records the proposal's initial fixed admission/collection/time bounds. `VersioningLimits` validates configurable retained-view (1–32), branch-profile (1–16) and normal-profile disk budget (1–65,536 MiB) values without consulting process environment; defaults are 8, 4 and 2,048 MiB. The upper disk-budget cap is an initial bounded policy, not a measured Qt limit. Later configuration integration must preserve these checks or document a measured revision.
