# VB-058 — Clean branch profile leases

Status: verified for the foundational lease boundary. The 2026-10-07 dependency audit found that an off-record child profile can be allocated without hiding or freezing its parent, so VB-036 is no longer a prerequisite for this narrower slice. The QML secondary-window route now treats a trusted branch token as ephemeral, rejects a shared/normal profile, retains exact branch host/profile/first-view identity, and refuses before navigation if lease registration or request-interceptor installation fails. A prepared branch remains hidden and undiscoverable until the separate VB-059 transaction publishes it. The original parent remains untouched.

A focused Qt 6.11.2 QML test passed three behavioral tests (five cases including setup/teardown) for distinct off-record profile instances, exact token ownership, parent/shared/wrong-view refusal, release and final-host destruction. The native `cargo xtask test versioning-clean-branch-profile` probe passed with two distinct public Quick profiles, memory-only cookie/cache policy, nonpersistent permission policy, two exact leases, separate synthetic cookie observations and exact release. The application branch-lease unit suite now passes 5/5 for typed reservation, duplicate/parent/child refusal, release order, rollback, capacity, and actual separate ephemeral application binding; the lease is embedded in `BrowserApplication`. The focused Qt source-boundary test passed. This is the foundational profile/lease boundary, not a production branch command, arbitrary-site localStorage campaign or whole-feature release qualification. Qt reports a default OffTheRecord path through `persistentStoragePath` even when configured paths are empty, so a nonempty reported path alone is not proof of disk writes. VB-059 must create and publish the actual child transaction before any user-facing branch is enabled.
