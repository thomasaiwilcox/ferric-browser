# VB-021 — Atomic structural commit publication and crash recovery

Status: verified at Ferric storage boundaries; browser-facing commit/list remains VB-022
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree atop the baseline
Affected requirements: `VERSION-001`, `VERSION-009`; invariants `VB-I01`, `VB-I04`, `VB-I12`

## Behavior implemented

The normal profile metadata worker has typed begin, structural-only publication, object-backed publication and recovery commands/completions. It checks that the command profile matches the UUID-bearing `profiles/<uuid>/browser.sqlite` path. A capture must first have a durable `staging` operation record; an unreserved, duplicate or interrupted operation cannot publish. Structural-only publication rejects non-structural categories and blob references. Object-backed publication revalidates each distinct referenced profile-local object with private-file, size, exact SHA-256 and directory fsync checks before an immediate SQLite transaction inserts the operation's completed state, commit, object index/link rows and fixed-code journal record together. A bounded 2-GiB unique-object limit applies to one commit. The worker sends success only after transaction commit. A failed foreign key, duplicate operation or corrupt object cannot leave a partial visible commit.

At normal-profile worker replacement, the application queues recovery before new versioning writes. Recovery scans a bounded number of private entries, atomically moves leftover staging directories and unreferenced objects into a fresh private quarantine batch without deleting bytes, fsyncs affected directories, and marks incomplete operation rows interrupted. Referenced objects remain in place. A recovery failure disables new captures for that profile; the old worker is retired before the scan, and application-owned active versioning operations block restart/profile replacement. The application queues same-kind requests with distinct tickets, and the worker emits typed success only after the transaction. The browser-facing capture route remains disabled; Qt explicitly refuses to present these internal completions as user capture success.

## Remaining boundary

VB-022 connects admitted application/reducer operations and a user-facing commit/list route to these storage tickets. Reads of a historical page must revalidate the object and return unavailable for missing/corrupt bytes; they must never substitute a live URL while claiming an archive. Native profile replacement must continue to quiesce any future blob jobs before recovery. Keep production capability flags false until later release qualification.
