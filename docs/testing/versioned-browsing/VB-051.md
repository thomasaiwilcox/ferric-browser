# VB-051 — Restricted archive profile and load path

Status: blocked; production archive viewing remains disabled pending the `versioning.archive_offline` capability and VB-057 qualification.

## Implementation

- Added a separate off-the-record `WebEngineProfile` with memory-only cache/cookie policy and no persistent storage paths.
- Added `FerricVersioningArchiveInterceptor`, which attaches only to an off-the-record profile and admits at most one exact, canonical `.mhtml` local main-frame `GET`. It independently checks a current-user-owned regular file, exact `0600` permissions, single link, and the 64 MiB archive cap. All other intercepted requests are blocked, including redirects and subresources that escape the MHTML representation.
- Added `FerricVersioningArchiveView.qml` as a separate untrusted-content surface. JavaScript, popup opening, plugins, local storage, WebGL, PDF viewing, fullscreen, drag/drop navigation, remote/file local-content access, hyperlink auditing and DNS prefetch are disabled; permissions, file/auth dialogs and fullscreen requests are denied; downloads and new windows are not accepted. The component contains no Ferric page bridge or privileged internal UI.
- The normal browser profile/interceptor is not referenced or modified by this component.
- The archive read path now resolves exactly one archive reference from the selected manifest, copies it through the file-only worker into a private per-operation staging file with a `.mhtml` suffix for native MIME recognition, checks its declared length and SHA-256 while streaming, and removes partial or explicitly closed view files through exact-operation cleanup.
- The Qt adapter publishes only the resulting local-file URL to the restricted component. Closing first navigates that view to `about:blank`; only the resulting blank-load callback schedules removal of the exact temporary file. A bounded blank-acknowledgement timeout retains the file and offers a retry rather than racing deletion with a still-live view. Owner changes are rechecked before activation.
- The disposable application archive fixture now authors a late-materialization regression: it rebinds the same logical profile after the manifest read and object materialization, requires a failed outer completion, and waits for removal of the exact temporary viewer file. This test is unrun pending the final campaign.
- The native WebEngine probe links the production `FerricVersioningArchiveInterceptor`, attaches it to the distinct off-the-record archive profile, and authorizes only the exact owner-only MHTML files it opens. Because the offscreen platform cannot qualify Chromium input dispatch and Weston headless lacks virtual-keyboard support, the probe requires an active Wayland desktop session; it opens a visible disposable 640×480 window, focuses that window through Hyprland when available, and sends QtTest mouse events to the exact controls in the active `QQuickWindow`. The production view and probe enable Qt's public [`focusOnNavigationEnabled`](https://doc.qt.io/qt-6/qml-qtwebengine-webenginesettings.html) setting while keeping JavaScript disabled. Native clicks demonstrably activate a button, link, and POST form in ordinary local HTML and links inside Qt-generated MHTML. A saved-MHTML form is present in the generated bytes but neither its POST nor GET click emits a Qt navigation callback or loopback traffic on this build. Chromium applies MHTML sandbox flags that include form restrictions ([policy source](https://chromium.googlesource.com/chromium/src/+/e6de25ee4229a5154a458c97fb6d0da7d8845b0f/content/browser/renderer_host/navigation_policy_container_builder.h)); this is a plausible explanation, not proof that Ferric's own form gate fired. The probe is fail-closed across both behaviors: if a future build emits the form navigation, it must be rejected at the view and intercepted at the profile; if no navigation occurs, no form request or network traffic is allowed. An archived external link independently exercises view rejection and profile interception. The revised native probe passes. No test exception weakens the production interceptor, and archive viewing stays disabled.

## Synthetic unresolved-resource MHTML — 2026-10-04

transparent native-click target spanning the bounded disposable view so a

The shipping isolated archive component is expected to render the main part,
and the probe now reads fixed in-memory counters from its actual production
interceptor. It requires intercepted CSS, image, and subframe requests to be
observed and blocked, zero loopback traffic after the native POST-form click,

retired. The probe also reports whether the form was rejected by the QML view

archive authorization so a prior file cannot satisfy the next fixture. This
uses the public Qt 6.11.2 `QWebEngineUrlRequestInfo::ResourceType` categories
for main frame, subframe, stylesheet, and image requests
([Qt documentation](https://doc.qt.io/QT-6/qwebengineurlrequestinfo.html)).
The first native run showed that Chromium suppresses these passive resources
before they reach Qt's interceptor. The subsequent 2026-10-04 campaign records
this outcome separately from interceptor evidence; see the result below.

The same unrun native fixture now keeps the archive overlay open while a
separate disk-backed source-profile view loads a successful loopback control
page. Its storage and cache paths are confined to the disposable operation
directory. It requires the source request to reach its own profile, the
archive to remain presented, and no unresolved archive-resource route to reach
the loopback server. This is a distinct-profile concurrency probe; it is not
the Ferric production profile or the full multi-window lifecycle
qualification. The probe uses Qt 6.11.2's public `storageName`,
`persistentStoragePath`, `cachePath`, and `httpCacheType` profile properties
([Qt WebEngineProfile QML documentation](https://doc.qt.io/qt-6/qml-qtwebengine-webengineprofile.html)).

## Renderer-side resource suppression — 2026-10-04; native campaign passed

`cargo xtask test archive` built and passed the hand-authored hostile MHTML
fixture plus the full native archive matrix. The synthetic archive retained
absolute remote CSS, image, iframe and POST-form references. The profile

only in-memory category totals, never URLs, referrers or payloads.

Keep the renderer settings, profile interceptor, and zero-network assertion.
Do not describe zero per-category counts as per-resource interceptor proof.
The tested Qt 6.11.2 fixture is a bounded native witness, not a universal MHTML
guarantee or the visible production multi-window/release matrix. Archive
viewing remains gated; VB-051 stays in progress pending the remaining
