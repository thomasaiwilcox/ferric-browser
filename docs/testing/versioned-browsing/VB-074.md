# VB-074 — Establish or reject a real source snapshot boundary

Status: verified (negative public-backend qualification; complete source boundary remains unsupported)
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree atop the baseline
Affected requirements: `VERSION-005`, `VERSION-006`, `VERSION-009`; invariants `VB-I06`, `VB-I07`, `VB-I12`, `VB-I17`

## Finding

The installed public Qt/QtWebEngine 6.11.2 cookie store has no exposed complete, consistent source read. `loadAllCookies()` is asynchronous and emits `cookieAdded` for loaded cookies, but supplies no finished event, count, revision token or atomicity claim. Individual mutation callbacks do not identify whether an addition came from initial load, explicit rescan, network `Set-Cookie`, JavaScript or another page. The public descriptor also lacks partition identity, so even a complete-looking callback count would not prove full-profile identity fidelity. The maintained decision is `versioning.cookie_snapshot = unsupported` on `qt-public-default`; no exact T0, seed source, merge base or production feature is enabled. The detailed mechanism review and unblock condition are in [cookie-snapshot-boundary.md](cookie-snapshot-boundary.md).

## Native stress and reference truth

`versioning_cookie_boundary_probe.qml` creates a real, disposable, disk-backed Quick profile under an isolated XDG root. `cargo xtask test versioning-cookie-boundary` runs one process to seed a persistent synthetic cookie and another to observe it after restart. The observer attaches before the first fixture navigation, dispatches `loadAllCookies()`, immediately issues a concurrent `setCookie`, then navigates to a loopback page that writes `document.cookie`. It also sets a three-second cookie, waits past expiry and checks a later browser request. A 127.0.0.1-only server records only synthetic presence booleans from real request headers: it confirmed the persisted seed survived restart, the JavaScript cookie remained, and the short-lived cookie expired. This is reference truth for those specific requests, not a profile-wide snapshot.

In three successful focused runs, the initial three-second observation window reported no callback for the persisted seed although the later browser request carried it. The concurrent setter did produce a callback. This does not establish that persistent cookies are *never* enumerated; it demonstrates why a quiet or partially populated interval cannot close a source read. The adapter epoch/sequence remained valid without overflow, and a later rescan event count was recorded only as a diagnostic. The test never converts that count into completion.

The Rust contract test uses synthetic positive capability metadata to isolate the read-boundary check. Long timeout, sentinel observation and repeated byte-equal reads all remain `Unknown`/`ObservedOnly`; `try_consistent_snapshot` returns `MissingReadBoundary`. With the real Qt capabilities, lossy identity refuses even earlier. Thus strict callers cannot proceed from the diagnostic mirror or from these heuristics.

## Tests

- `cargo xtask test versioning-cookie-boundary` — passed repeatedly on offscreen Qt/QtWebEngine 6.11.2; output reported `initial observer callback: no` with positive browser-request truth. Earlier test-first attempts that required this callback failed; they were corrected to avoid treating the callback window as a guaranteed completion condition.
- `cargo test -p ferric-browser-application --locked --offline versioning::cookies --quiet` — 18 passed, including the new false-boundary regression.
- `cargo xtask check --locked --offline` — passed on final source, including native cookie boundary/adapter/API probes, 57 offscreen QML passes and workspace tests.
- `cargo clippy --workspace --all-targets --locked --offline -- -D warnings`, `git diff --check`, pack validation and checksum verification — passed.

## Privacy and ownership

Only fixed synthetic cookies and a disposable persistent profile were used. The two native processes share only their test XDG root, which the runner deletes and verifies absent after completion. No normal user profile, external account, Chromium database, private API or remote-debugging endpoint was accessed. The loopback server stores only synthetic presence booleans, never Cookie headers or values. The runner whitelists fixed failure labels and rejects secret fixture markers in stdout/stderr. This test does not add cookie persistence to Ferric production code.

## Remaining boundary and next slice

A new reviewed backend must supply full identity/attribute fidelity and a genuine complete consistent read boundary for an exact scope, then pass persistent, concurrent-mutation and expiry qualification. The separate destination seed/read-back and controlled-apply gates remain unsupported. The next ledger-selected slice is `VB-075`, the destination seed/read-back contract for supported fixtures; it must not interpret this negative source result as permission to seed arbitrary parents.
