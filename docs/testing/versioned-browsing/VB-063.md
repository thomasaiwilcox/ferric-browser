# VB-063 — Branch popup and permission isolation

Status: in progress. The exact branch-popup route is implemented. Disposable native scripted-popup, `target=_blank`, same-origin redirect and fresh notification-prompt journeys pass; certificate/saved-trust and broader OAuth-style cross-origin flows remain.

A clean branch now preflights its exact published host/profile/first view, child UI and request interceptor before allocating a popup. The source check also permits a future window-branch page view only when that exact view is registered by the same child host with the same off-record profile, child UI and interceptor; an unregistered, stale or rebound view is refused. The popup starts hidden and is registered and opened only after a second exact-owner check; failed checks destroy it without opening the request or falling back to the normal profile. The popup uses the branch's off-record profile, request interceptor and child permission UI, and is labeled transient. A popup opened by that popup repeats the same branch-owner check and stays with the originating branch profile. Sensitive permission, certificate, authentication, WebAuthn, desktop-media and file prompts recheck the owner and deny/cancel if it is stale. The branch host's existing teardown waits for its owned popup windows before profile release.

`permission_decision` already omits durable profile rules for a transient child UI; its Qt profile uses `AskEveryTime` permission persistence. Permission and certificate requests remain routed to that child UI and fresh prompt surface, not the parent normal UI. These code paths still need native confirmation against saved trust exceptions and redirect flows. No production clean-branch capability is enabled.

Evidence: `qmltestrunner -input crates/ferric-browser-engine-qt/tests/qml/tst_clean_branch_popup_ownership.qml` under offscreen software Qt passed 9/9 on 2026-10-07. The fixture checks exact owner admission, registered extra-view admission through the tab-capable native creation host, unregistered/stale extra-view refusal, cross-profile and wrong-permission-UI refusal, stale/rebound owner refusal, off-record source requirement, and transient permission/interceptor requirements. The group child now passes the branch token, exact profile/interceptor and child permission UI into the existing popup host and refuses stale branch views before popup or sensitive prompt handling. The feature-enabled browser build passed. Native popup and prompt tests remain.

A disposable Wayland process loaded the loopback `/popup` fixture in both the original normal parent and a structurally forked ephemeral child. The child web document and its `open popup` button were visible in its PID-scoped AT-SPI subtree. An accessibility action returned success, but no popup frame appeared; the compositor still had a different application focused, so the action did not establish a trusted user gesture. This native attempt is inconclusive, not evidence that popup policy passed or failed. The browser, fixture server and exact disposable profile were stopped and removed.

## Cross-origin loopback callback round trip — 2026-10-08

The native scripted-popup and `target=_blank` routes now pass through an
absolute HTTP redirect from `127.0.0.1` to `localhost`, then an absolute
callback redirect to `127.0.0.1`. These are distinct web origins on the same
disposable loopback fixture. The test counts both identity-provider-shaped
intermediate requests and final callback requests; after each round trip,
the popup still has the exact clean child's off-record profile, permission UI
and interceptor. Both popup/child pairs complete their explicit close prompts
without affecting the normal parent. The extended native journey passed
through Cargo and five further fresh-process runs. The complete post-extension
workspace gate and feature-enabled browser build passed.

This is a local cross-origin ownership test, not an actual OAuth integration,
external identity-provider compatibility test, or saved-certificate-exception
test. Those and other permission categories remain open; the production gate
stays disabled.

With this separation, the combined journey passed through Cargo and five
