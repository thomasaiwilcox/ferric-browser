# VB-071 — Narrow public Quick cookie observation adapter

Status: verified (bounded native observation primitive; strict snapshot remains unsupported)
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree atop the baseline
Affected requirements: `VERSION-005`, `VERSION-009`; invariants `VB-I03`, `VB-I06`, `VB-I07`, `VB-I12`, `VB-I17`

## Behaviour

The C++-only `FerricVersioningCookieAdapter` attaches to an exact public `QQuickWebEngineProfile::cookieStore()` pointer. `QPointer` guards both profile and store; Qt signal connections use a receiver `QObject` context and a captured epoch so queued callbacks from a replaced or destroyed profile cannot retarget a new owner. It copies bounded raw name/value bytes and a closed set of cookie attributes into a private 64-item queue. Each item carries its profile epoch and monotonic sequence. The callback does no logging, persistence, identity matching, Unicode normalisation, snapshot classification or application work.

Overflow or an oversize item invalidates the observation state and clears the partial queue. Reattachment begins a fresh epoch; profile or store destruction detaches, drops queued values and invalidates the old epoch. The adapter has no QML registration, `Q_INVOKABLE` method, QVariant projection or IPC serializer. An explicit `requestEnumeration()` invokes the installed public `loadAllCookies()` and reports only whether that void-returning request was dispatched. `ObservedAdded`/`ObservedRemoved` name callback shapes, not authoritative creation/deletion history; a rescan cannot be distinguished from live additions through this public signal set.

This is a diagnostic observation primitive, not a complete cookie snapshot, branch seed or merge writer. It does not change the unsupported identity, source-boundary, read-back or controlled-write gates.

## Focused evidence

- The test-first native harness failed to compile while the adapter header was absent. Its first standalone Quick-profile run then observed no cookie callback; loading the existing disposable off-record QML view fixture initialized the real Quick profile path and made the native observation test meaningful.
- Installed Qt 6.11 public headers expose `QQuickWebEngineProfile::cookieStore()`, `QWebEngineCookieStore::loadAllCookies()` and `cookieAdded`/`cookieRemoved` signals. They expose no enumeration-finished callback or revision token; the adapter does not invent one.
- `c++ -std=c++17 -fPIC -Wall -Wextra -Werror -Wno-sfinae-incomplete` against the real installed Qt headers, then the disposable probe under `QT_QPA_PLATFORM=offscreen` and native Wayland — passed. The probe tests synthetic added and removed raw-byte observations with increasing sequence, explicit enumeration dispatch, queue overflow invalidation, fresh epoch after rebind, and profile destruction with an observation queued.
- `cargo xtask test versioning-cookie-adapter` — passed. The task runner captures native output, rejects the fixed synthetic secret/name markers in stdout and stderr, and prints only a fixed non-secret result.
- `cargo xtask check --locked --offline` — passed, including 57 offscreen QML passes, native archive/cookie/Quick-adapter/HTTPS probes, formatting and workspace Rust tests. The final added removal-sequence assertion was rerun through the focused native task afterward; production adapter source was unchanged.
- `cargo clippy --workspace --all-targets --locked --offline -- -D warnings` and `git diff --check` — passed. Existing Qt/GCC header warnings were non-fatal; the strict standalone adapter/probe compile passed with the known header warning suppressed.

## Privacy and ownership review

The test uses a fresh off-the-record Quick profile and fixed synthetic cookies. No normal user profile, external account, private Qt API, debug port or Chromium database is accessed. Values can be drained only by native C++ code; a future application bridge must preserve their bounded memory-only treatment and emit a separately redacted projection. Queue clearing is not a claim that Qt/Chromium copies, allocator memory, swap or crash dumps are erased. A missing callback or quiet enumeration interval remains unknown rather than an empty jar.
