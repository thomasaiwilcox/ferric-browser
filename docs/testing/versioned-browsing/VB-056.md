# VB-056 — Add capture cleanup, corruption and privacy fault tests

Status: verified for the declared capture-cleanup, corruption, privacy, and
diagnostics-preview criteria on the tested Unix/Qt configuration. This is not
an exhaustive claim about every possible diagnostics sink, filesystem fault,
or capability-skipped native journey; archive production gates remain
separate.

## Implemented fault coverage

- Storage fixtures already exercise restart quarantine of abandoned staging and
  unreferenced immutable objects, repeatable recovery, corrupt-reference
  quarantine, symlink/path substitution rejection, incomplete and oversized
  captures, digest mismatch, cancellation during chunked hashing, and
  interruption at object-install durability checkpoints.
- Restricted archive materialization now has authored missing-object and
  same-length-corrupt-object checks that require exact viewer staging cleanup.
  These storage regressions remain unrun.
- Budget fixtures exercise reservation release, rejected over-budget object
  publication, preservation of pinned commits, and rejection without claiming
  a hard filesystem-wide quota.
- Worker command and successful completion `Debug` are covered for page
  payload, private stage/view path, and digest redaction. Application capture
  policy fixtures reject private-profile
  persistence before a preview can be created. Structural window and context
  capture regressions now also require transient owners to be refused and
  structural context manifests to contain no archive object, sidecar object,
  or page-capture interval/category payload.
- File-worker completions now carry a closed failure enum rather than raw
  strings, with fixed `Debug`/`Display` text. The application storage bridge
  maps these categories to operation-specific diagnostics instead of
  forwarding worker details. Authored regressions exercise all four
  completion variants and every closed failure category, including fixed
  `Display` text and exact diagnostic routing, with synthetic path, page-secret,
  and digest sentinels; execution remains deferred.
- The existing native page-save probe exercises auto-start cancellation,
  interrupted/empty outcomes, unrelated downloads, mismatched correlation, and
  cleanup after a bounded invalid-path save. The stalled-save case now also
  requires a confirmed `DownloadInProgress` state before cancellation and
  checks that the terminal callback is `DownloadCancelled` with no output file.
- Late page-save callback quarantine has fixed 128-entry bounds for both IDs
  and exact stage paths. The ID entry is consumed on its callback; canceled
  stage-path tombstones live only for the process lifetime because the public
  API gives no guarantee that no further stale request callback can arrive.
  Capture fails closed rather than evicting an unresolved identity.
- The retirement policy is now isolated in a small QML helper with authored
  coverage for malformed IDs, duplicate retirement, capacity exhaustion,
  no-eviction behavior, and persistent exact-path tombstones after an ID
  callback is consumed. The helper fixture is not run yet.
- Added an application lifecycle case that starts the bounded page-archive
  reservation/staging pipeline, waits for the exact object worker's temporary
  hash file, and retires the normal profile during the 32 MiB hash/copy. It
  requires the temporary file to be removed, no partial object to be installed,
  and no commit to be published after profile close.
- Added a second application race fixture that rebinds the same logical
  profile to a fresh native-owner generation after holding a completed object
  worker result but before application routing. The late callback remains
  unpublishable under the new owner; the complete immutable object is left
  unreferenced for normal retention cleanup, and no commit may be published.
  Both lifecycle cases are authored only; their final execution is deferred.

## IPC and command Debug redaction — authored 2026-10-05; not run

The IPC data types' derived `Debug` projections exposed request IDs, arbitrary
parameters, response/event payloads, protocol diagnostics, hello identities,
command arguments and routing context. IPC framing errors also formatted raw
I/O and serde diagnostics, which can contain local paths or attacker-provided
input. These diagnostic projections now redact dynamic values at source;
frame error variants remain typed, with only fixed dynamic-error text in
`Debug`/`Display`. Request-cache diagnostics expose entry counts rather than
request IDs or cached values, and instance path/error Debug/Display
projections omit local paths and owner text. Serialization and in-process
request/response data are unchanged. Sentinel regressions cover
request/response serialization versus debug output, events, protocol/public
errors, frame errors, command invocation,
cache state, instance paths and errors. They are authored but have not been
built or run under the final-verification deferral. This does not establish
that every application/Qt diagnostic channel is free of dynamic data; the
broader privacy and native lifecycle campaign remains open.

The IPC error-text sanitizer also now removes POSIX, relative and drive-letter
local paths, plus values under path/file/directory/socket keys, from response
messages and nested string details. Its existing response sentinel fixture
now includes local profile and socket paths; it remains unrun.

External-process stderr redaction now also suppresses cookie and authorization
values in HTTP-style header lines, `cookie=...` tokens, and URI query keys.
Prefixed log text is retained only after applying the existing URL/path
redaction. This protects the explicitly requested operation stderr projection
as well as editor/userscript diagnostics. Sentinel coverage is authored but
unbuilt and unrun under the end-of-goal verification deferral.

The storage diagnostic pass also found that download destination errors and
crash-marker errors still included the raw path and OS error message in
`Debug`/`Display`. Those projections now emit fixed categories and redact
dynamic path/message data; authored sentinel regressions cover invalid,
colliding and I/O download paths plus crash-marker I/O. The typed fields remain
available to explicit in-process consumers. These regressions are unbuilt and
unrun under the verification deferral; broader diagnostic and fault coverage
remains open.

Core URL and navigation error `Display` text now also omits caller-controlled
scheme, malformed-input, and external-target strings. Direct command-dispatch
errors use redacted variant-only `Debug` and fixed-category `Display`, so
unknown command text, missing-argument labels, and external URI recipients do
not flow into diagnostics. Typed variants still retain the exact target for a
caller that needs it for an explicit decision. Sentinel regressions are
authored but unbuilt/unrun; this does not qualify all application, Qt, or
platform logging paths.

The remaining compositor and IPC-decoder error types now also redact raw
backend, socket, and malformed-command text in direct `Debug`/`Display`
projections. `IpcCommandError` still carries its typed diagnostic context into
the existing public-error response path, where the response scrubber applies;
the direct formatting regression requires the synthetic payload sentinel to
stay out of debug/status text. These tests remain unbuilt/unrun and do not
qualify every platform logging sink. The internal `IpcRoute` debug projection
also now emits selector kind and presence bits rather than runtime IDs, profile
or context labels; its sentinel regression is authored but unrun.

`ReduceError` no longer formats opaque runtime profile/window/tab IDs through
derived `Debug` or by delegating `Display` to it. It now emits the stable error
category and fixed text; an authored regression checks synthetic ID sentinels
across both projections. It has not been built or run.

`SessionError::Invalid(String)` is publicly constructible, so its previous
`Display` passthrough could emit arbitrary caller text despite the redacted
`Debug` projection. It now emits a fixed category, with an authored sentinel
regression across both projections. The session tests have not been run.

The same audit found that `NewWindowRestorePlan`'s custom Debug output still
exposed both the source UUID and runtime profile identity. Both are now fixed
redaction markers, with sentinel assertions added to the existing owner-rebind
regression. This coverage is also unrun.
