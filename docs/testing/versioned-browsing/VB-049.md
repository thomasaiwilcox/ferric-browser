# VB-049 — Bounded per-frame capture with origin policy

Status: verified  
Baseline SHA: pack baseline `deea458d92bcf6d8fbea7b04af17823b5882cc1b`  
Implementation SHA or uncommitted-tree description: shared uncommitted worktree; changes are not committed  
Affected requirements and invariants: VERSION-003, VERSION-009; VB-I04, VB-I05, VB-I12, VB-I14, VB-I15

## Behavior or investigation

- Added `collectFrameTree` to the reviewed page-state helper and a runtime-services entry point. It uses the public QML `WebEngineView.mainFrame`, `webEngineFrame.children`, `isValid`, `url`, and `runJavaScript` surfaces. No private page pointer or Chromium API is used.
- Capture is serial and bounded by caller-clamped limits: 16 frames, depth 8, 4,096 total DOM nodes, 256 candidates, 512 positions, 256 controls, 128 editable values, 64 KiB editable text, 128 exclusions, and the existing 256 KiB sidecar limit. Per-frame results retain explicit coverage; any frame-level omission marks requested categories partial.
- Only HTTP(S) child URLs matching the admitted top origin are sent the collector. Cross-origin and opaque/non-HTTP frames are excluded before collection; the page helper independently verifies actual `location.origin` and the exact route. Same-origin frame route fingerprints are computed in the isolated page helper.
- Child frame values are held directly across each asynchronous callback and rechecked for validity and unchanged URL. Navigation, deletion, renderer errors, depth/count limits, and denied origins become fixed categorical exclusions without serializing frame URLs or names. IDs are ephemeral sidecar foreign keys, allocated for one capture and never used as persistent frame identity or restore authority.
- Each participating frame is stamped with the capture nonce in its isolated ApplicationWorld. After the serial tree walk, the helper probes every captured frame again; a same-URL reload loses the document-local stamp and invalidates the aggregate instead of allowing two documents' results to be combined.
- Core sidecar validation now admits explicitly parented same-origin frame records and the new `deleted-frame` / `navigated-frame` exclusion categories; geometry restore continues to consider only frame 0.
- QML tests cover denied cross-origin URLs, URL non-disclosure, opaque children, and frame-count truncation. Additional native cases now load the fixed same-origin/cross-origin fixture tree from a live loopback server, admit the same-origin child through the collector, and exercise child removal, navigation, and reordering between capture and the post-archive mutation probe.
- The `versioning-geometry` xtask probe starts the fixture server on an ephemeral loopback port, stages the QML test and its two JS dependencies in a disposable directory with the generated fixture URL, and requires the combined frame tree to pass Rust `PageStateSidecar` admission. The native runner is capped at 45 seconds. This closes the prior gap where the documented positive same-origin child test did not exist in the QML test source.
- Before merging any renderer callback result, the frame coordinator now rejects non-string or over-256-KiB responses, over-budget candidate/position/control/coverage/exclusion/editable arrays, and malformed or over-budget editable values. A malformed top-frame result fails the capture; an invalid child result becomes a fixed categorical exclusion. Rust sidecar validation remains a separate publication boundary.

## Privacy and ownership review

- Cross-origin frame URLs, names, and paths are not returned in the sidecar; exclusions disclose only fixed categories and bounded counts.
- Frame IDs refer only to records within one sidecar. They never authorize restore or compare frames across captures. Child geometry restore remains unsupported.
- The integrated collector receives a Rust-issued one-use capture request and VB-050 binds its request and interval boundaries to the exact owner/document operation. The QML utility itself is not an authorization source.

## Renderer field admission at the frame callback — 2026-10-03

The QML frame coordinator now requires the exact reviewed field set on the
renderer result and each nested frame, candidate, position, control value,
coverage, exclusion and editable value before merging any of them into the
aggregate sidecar. Unknown fields fail the top-frame capture or become a fixed
`unsupported` exclusion for a child. This is an early rejection boundary; Rust
still independently rejects unknown nested sidecar fields before any result is
held for publication.

Synthetic callback regressions inject command and URL fields at the root and
nested locations. A separate two-frame callback keeps the clean root, excludes
the injected child categorically, and emits none of the child's command or URL
markers. `cargo xtask test versioning-geometry` passed the live Qt
page-state suite and Rust admission, including the positive same-origin tree.
The focused core parser test and the application callback test passed: a
nested command/URL payload was refused without retaining sidecar bytes,
summary or interval, while a subsequent clean response was accepted. These
tests establish the injected-field path, not a general native audit of every
ordinary UI/IPC projection; VB-049 and the release gate remain open.
