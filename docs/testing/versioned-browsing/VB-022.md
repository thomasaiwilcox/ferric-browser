## Later same-profile publication hardening

A later workspace run exposed an intermittent two-owner context-commit
failure. Diagnosis found that a stale schema preflight could replay table
creation after another owner committed it, and concurrent database opens
could report a transient SQLite lock. The metadata store now re-reads
migration state under its write lock and serializes same-process opens for
the same canonical database path. A second application owner joins the first
owner's recovery result rather than running restart quarantine against a
live capture. Fresh/upgrade stale-preflight regressions failed before repair
and pass afterward; storage concurrency and same-profile live-capture
regressions pass. The previously intermittent 159-test application suite
passed 20 consecutive runs after the repair.
The complete `cargo xtask check --locked --offline` also passed on the final
source, including 167 QML passes, five gated skips, native probes and all
workspace Rust suites. This coordinates recovery only among owners in the
same process; cross-process ownership still relies on the existing profile
lock and is not qualified by these fixtures.

An actual child-process kill fixture now stops object-backed publication at
six checkpoints: before the transaction, after marking the operation complete,
after inserting the commit row, after its object link, before SQLite commit,
and immediately after it. On reopen, every pre-commit kill leaves the durable
reservation in `staging` with no commit, object-index row, link or capture
journal entry. The post-commit kill leaves all four rows and the completed
operation together; the immutable object bytes remain intact throughout.
The focused fixture and storage versioning suite passed 72/72, with strict
storage Clippy. This establishes process-death SQLite atomicity at those
instrumented boundaries, not power-loss/fsync-failure durability or a
browser-facing acknowledgment after the post-commit kill.
The complete `cargo xtask check --locked --offline` passed afterward,
including 167 QML passes, five environment-gated skips, native probes, and
the workspace Rust suites.

The reducer now owns stable logical window/page IDs for structural capture; a removed runtime tab releases its mapping. The application validates a normal durable profile and exact native owner, projects the exact admitted scope and validates the structural-only manifest before applying the identity-binding reducer event as the final fallible mutation. The manifest records the single-step revision that the binding event commits, and the returned effects are forwarded through the ordinary adapter path. No unproven URL is treated as replayable. The application then submits a durable staging reservation and publishes that exact manifest only after the reservation succeeds. Only the publication acknowledgment emits `CommitEvent::Durable`; failures produce a payload-free terminal event. Profile replacement/restart refuse a pending capture, and profile close reconciles its exact storage ticket.

The metadata worker provides bounded, redacted current-profile listing and exact-ID info. Listing fetches one bounded lookahead row and returns only the requested page plus an exact `has_next` bit, avoiding both an unbounded count query and a spurious next page when the result count is an exact multiple of the page size. Info validates the stored manifest's byte limit, SHA-256, schema and owner before projecting counts, coverage, unavailable URL reasons, object counts and source identifiers; it never returns the message or page URL. Application read tickets are correlated to typed read events and the exact native-owner generation, not raw storage completions; late list/info/diff/delete callbacks from a replaced native owner fail closed. The first stale diff callback drops any buffered manifest and emits one failure; its paired late callback is ignored. Qt receives a pending-only command/IPC acknowledgment and displays commit success only after the application reports durable publication. Disposable-profile tests find a committed ID after application restart and confirm by reading the test database that a later tab pin mutation did not change the admitted manifest bytes. Private and ephemeral profiles, plus a different runtime profile trying to write the active database, are refused.
