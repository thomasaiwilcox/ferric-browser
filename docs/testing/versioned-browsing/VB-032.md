## Behavior

The application has a separate `PreservationIntent::ExplicitStash` policy. It does not weaken or call the ordinary suspension/discard path: ordinary suspension still refuses dirty or unknown editable state. A stash observation is an exact captured tab/document plus categorical native evidence, with no field values or editable text. Admission re-resolves that captured scope and owner, checks renderer and resource state, and refuses inactive or unqualified views, in-flight navigation, any active or unknown download/prompt/capture/live-call/DevTools/audio/browser-operation activity, and unknown editable state. Dirty work additionally requires a qualified dirty-editor primitive. Refusals have fixed, content-free native status copy.

Every eligible explicit stash, including a clean page, requires a fixed-copy warning that live work is volatile and not saved. Dirty pages receive dedicated unsaved-work wording. The application prepares an immutable preview for its exact sensitive operation and uses the VB-016 native-decision proof and one-use permit. Immediately before consuming consent, it rechecks the current owner, document, eligibility and dirty classification. A changed dirty classification invalidates the accepted preview. The preview DTO has a separate `volatile_work_risk` flag; it does not mislabel unsaved work as authentication risk.

This slice returns an authorized captured owner but never hides, freezes or destroys a view. The native decision sink is trusted-adapter-only, not a page or IPC consent boolean. The caller must source categorical evidence from the exact native view and the VB-041 runtime qualification; a caller-provided `freeze_primitive_qualified` boolean is not itself a production qualification. VB-033 must recheck eligibility during native prepare/freeze acknowledgement and leave the view visible on any failure. No production stash command is enabled.
