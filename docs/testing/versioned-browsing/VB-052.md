# VB-052 — Archive detail and explicit open-live transition

Status: blocked; stored archive viewing remains disabled pending the `versioning.archive_offline` capability and VB-057 qualification.

## Implementation

- Commit details show the saved timestamp, scope, page/object counts, and per-category archive/page/cookie coverage.
- Archive viewing is presented as a separate action and remains disabled until `versioning.archive_offline` is released. It is also disabled when the commit reports missing or quarantined objects.
- The live path is explicitly labeled and requires a second confirmation. The confirmation explains that it opens a new normal-profile window, loads current pages from replayable safe URLs, may send network requests, and does not display the stored archive or restore page contents/forms/secrets.
- Both the list and detail paths route through commit detail before offering live restoration; there is no one-click list-row restore.
- The stored-archive request now resolves one exact manifest archive object, materializes it with bounded digest verification into a private staging file, and routes the file to the isolated archive component. One view is admitted per application instance. The viewer is removed only after it reports a successful blank navigation; cleanup has bounded retries, and the UI action remains disabled behind the offline-isolation release gate.
- After an explicit archive-view request, trusted application metadata supplies the recorded source URL, archive completion time, and archive/page-state fidelity labels to the separate viewer chrome. The source is rendered as plain-text metadata only, warns that private URL parameters may appear, and never becomes a navigation target; debug output redacts it.

The storage regression now also covers missing and same-length-corrupt archive objects, requiring materialization to fail and remove its exact temporary viewer staging directory. The application fixture additionally rebinds the native owner after digest-verified materialization but before activation; it requires the caller to receive a failure, forbids an active view, and waits for exact temporary-file cleanup. These regressions are authored but have not been run.

The application now marks a staged archive file as potentially in use when

## 2026-10-03 real storage-worker refusal and safe retention

The shipping `Main.qml`/`BrowserUi` shutdown journey now also exercises a
real cleanup error. After a verified MHTML is presented, the test
changes only its disposable private viewer leaf to mode `0644`. The worker's
exact-file removal refuses that unsafe leaf, leaving it in place. Earlier
runs observed bounded retry status and one successful test-side permission
repair, but another repeat showed the worker can exhaust its immediate
retries before the test restores permissions. That race cannot qualify a
deterministic successful retry. The revised native journey leaves the file
unsafe through shutdown, requiring blank acknowledgement and safe retention
instead. Qt GUI journeys run in separate processes, avoiding unsupported
repeated application construction in one process.

The revised campaign qualifies the real-worker refusal/retention branch,

## Sanitized source metadata presentation — 2026-10-04; not run

The archive chrome previously displayed the manifest's recorded source URL
directly. Although the label was plain text and non-clickable, Unicode
directional controls could still visually reorder or spoof that metadata.
The adapter now applies Ferric's existing URL presentation sanitizer before
placing the source in the QML property; known credentials/sensitive query
keys and fragments are redacted, and directional controls are neutralized.
The archive remains offline metadata only and the displayed value is never
used as a navigation target.

An authored adapter regression checks credential/token/fragment redaction,
bidi-control neutralization and the absent-source case. It has not been built
or run under the end-of-goal verification deferral. The surrounding Qt native
archive UI and profile-isolation qualification remain separate release gates.

## Bounded archive-title presentation — 2026-10-04; not run

The isolated archive component previously exposed the saved document title
directly to its heading. It now caps the displayed title at 512 UTF-16 code
units, replaces bidi and control characters, and uses that sanitized property
for both chrome and the load notification. The stored MHTML and page content
are not modified. A native archive fixture now includes a directional override
in its title and distinguishes the raw WebEngine title from the production
component's safe display value; a source-boundary regression also protects the
bounded sanitizer wiring. These regressions are authored, not built or run.

## Complete bidi-control display filter — 2026-10-04; not run

Source review found the first display sanitizer handled overrides and isolates
but omitted Arabic Letter Mark (U+061C) and left/right marks (U+200E–U+200F).
The shared Rust display sanitizer and isolated archive-title sanitizer now
cover the complete Unicode `Bidi_Control` property set: U+061C, U+200E–U+200F,
U+202A–U+202E and U+2066–U+2069. The Rust URL-source fixture and native MHTML
title fixture now include the previously missing marks; these regressions are
authored but not run. The exact property ranges are from Unicode's
[PropList.txt](https://www.unicode.org/Public/UCD/latest/ucd/PropList.txt).
