## Behavior

`ApplicationState` privately owns `VersioningState`; consumers receive only a read-only view. Branch names, parent/root lineage, immutable fork references, profile/application owners, native live binding, inheritance request/report, ordered logical-page membership, working revision, last commit, lifecycle and retained-view membership are modeled without Qt handles or disk state. The root `main` is per application/profile lineage; child names are unique under that lineage using bounded case-folded whitespace-normalized keys. Stored IDs, not names, remain authoritative references.

All transitions enter through `Event::Versioning` in the existing core reducer. Preparation checks parent ownership, fork presence, self/ancestor cycles and the eight-level nesting limit. Publication checks exact inheritance and uniqueness of live profile-instance ownership. Working updates require the expected revision and unique bounded logical pages; no update changes the fork reference. Failure, retention, resume, close, selection and drop transitions reject invalid lifecycles. A live, preparing or retained branch cannot be dropped; retained views and child references separately prevent close/deletion. Rejected transitions leave state and revision unchanged. Accepted versioning transitions advance the logical reducer revision without emitting the ordinary `PersistEffect::Snapshot` recovery write.

The runtime event projection contains only a fixed action kind; branch labels do not enter JSON IPC. Branch-name `Debug` is redacted. This is domain state only: no production branch command, native branch host, durable commit or snapshot-cookie capability is enabled.

## Privacy and ownership review

Core stores no Qt pointer, page text, URL, editable value or cookie material in these records. Native profile-instance IDs are runtime-only references, not serialized authority. The reducer does not move views or create profiles. `SnapshotVerified` is representable as a typed report but cannot be reached through a user command here; later application integration must require a scoped capability certificate before publishing that report. Existing negative cookie gates and production-disabled flags remain unchanged.
