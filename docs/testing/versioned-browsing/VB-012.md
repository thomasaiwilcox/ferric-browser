# VB-012 — Operation state and cancellation semantics

Status: verified (application protocol only; native integration remains open)
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree atop the baseline
Affected requirements: `VERSION-009`; invariants `VB-I01`–`VB-I05`, `VB-I12`, `VB-I15`–`VB-I16`

## Behavior

`BrowserApplication` now owns a versioning coordinator and one application-owner identity. A trusted adapter explicitly binds each native profile-instance lifetime; admission resolves a captured tab or window scope through a read-only runtime view. The envelope carries the operation ID, native owner, immutable captured members, configuration revision, privacy policy, expected logical revision, deadline, cancellation generation and mutability kind. No callback path resolves active focus.

The coordinator enforces typed forward states, explicit consent and callback tickets, one active mutating operation per native owner, a 16-entry mutation queue, an overall 17-operation in-flight bound and a 32-entry recent-terminal bound. Clock and ID sources are injectable. Consent expires and is tied to the admitted configuration revision. Owner replacement and close invalidate attached operations. Cancel and deadline effects name only the operation's own stage ticket; cleanup is idempotent, since a callback may arrive after cancellation. Terminal `Partial` and `OutcomeUnknown` are distinct from `Failed` and `Completed`. No cookie API or persistence write was introduced.

This is an application protocol, not a production command or native collector. The adapter must execute returned cleanup effects and poll expiry; future integration must validate original document tokens for page results and wire native profile close/replacement events to these methods.

## Privacy and ownership review

No page body, URL, editable value, cookie value or Qt pointer enters the envelope, callback ticket or effect. Private and ephemeral admission is marked memory-only; no durable write authority is granted. Operation tickets are opaque, owner-bound and bounded; current focus cannot redirect a late result. Stage cleanup is scoped to its exact ticket. The negative general-cookie capability gate and production-disabled state are unchanged.
