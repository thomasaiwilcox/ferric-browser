# VB-053 — Conservative geometry restore

Status: verified for the bounded geometry-restore slice; production page continuity remains gated.
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree atop the baseline.

The core sidecar DTO now builds a geometry-only plan from independently qualified stored and current observations. It requires the same top-document origin and route fingerprint, matches bounded identity and context hashes, rejects repeated IDs/names even when context differs, and skips changed or unsupported targets. Candidate numbers are hints, never selectors or authority. The plan emits a bounded JSON request with only hashed hints and numeric offsets; it does not include editable values, selection, media state or keyboard scroll policy changes.

The ApplicationWorld page helper rechecks the live origin, route, document identity, candidate uniqueness, visibility, scrollability and coordinate range immediately before a one-shot application. It reports partial/limit outcomes and never focuses a target or changes the explicit keyboard scroll owner. Synthetic Rust tests cover unique/duplicate/changed/route cases. Native QML fixtures cover nested scrollers, duplicate IDs, changed descriptors, wrong route and traversal limit.

The live helper now matches a uniquely identified scroll area by its bounded fingerprints and context even if unrelated eligible elements changed the scan order. The plan's candidate number is only a hint. A repeated descriptor in one restore request is rejected before applying offsets, and the existing live duplicate-identity check still skips ambiguous elements. A native QML regression for reordered candidates and repeated request descriptors has been added but not run yet. A coordinator fixture now also exercises its bounded readiness timeout and stale-destination callback cleanup; it is authored but not run.

The coordinator now scopes asynchronous cleanup to the callback's exact restore request. A late callback from an older request discards only that request's sidecar and cannot clear a newer restore already active in the coordinator. A QML regression covering this replacement race is authored but has not been executed.

The storage worker has a bounded read operation for the sidecar linked to one exact commit and logical page. It resolves the object through the committed manifest, rejects ambiguous page identity or a non-sidecar reference, verifies the profile-local object’s length and SHA-256, and wraps returned bytes in a debug-redacted type. The application admits reads only for the selected restored descendant and parses the payload internally. Both the original secondary-window path and the new tab-capable primary restore surface handle the exact sidecar-ready action. The primary restore coordinator maps the destination tab ID to its exact active native view, requires the normal profile, then checks tab, URL, and navigation epoch around both ApplicationWorld calls. It sends the live observation back through the application planner, which verifies the generated nonce/fingerprint and route before emitting a geometry-only request. A bounded readiness/callback window discards the request on timeout, navigation, or view replacement. No editable values, selection, media state, or keyboard scroll policy are applied by geometry restore.

The page-capture path now collects, validates, and publishes an optional sidecar alongside the archive under the interval protocol described in VB-050. Structural-only commits still correctly have no sidecar, so restore remains optional and fails closed when the selected committed page has none. The integrated Qt/application path and the new exact destination-document guard have not yet been reverified; verification remains deferred. Production capture and archive viewing remain gated independently.

## Native destination application — 2026-10-03

A new disposable native journey now captures two nested scroll positions on
the loopback GET document, publishes a real Qt MHTML archive and collector
sidecar, shuts down, reopens the durable profile and verifies the committed
sidecar contains both offsets. It then starts a fresh browser window with the
exact commit. The ordinary restore path loads the safe page and applies both
offsets to the destination DOM; no test-only method starts the restore or
applies the geometry. `cargo xtask test archive` passed all 20 journeys,
including this one. This proves one static selected-page capture-to-restore
path, not arbitrary changed live sites or multi-page destination lifecycles.

The journey exposed two production integration defects. First, a read-only
preview of future IDs consumed the process-shared allocator, so later plan
validation could never reproduce its own IDs. Identity previews now fork a
local allocator snapshot; stale plan/revision checks and actual post-allocation
ID checks remain. Second, profile bootstrap requested restore before its
original `about:blank` load had settled; a late callback could retire the
one-use sidecar intent. The destination now waits for that exact blank view
to finish within five seconds and refuses changed/nonblank destinations.
Application admission also retains the intent across Qt's exact provisional
URL update only while the tab remains provisional; a different route still
invalidates it. Focused core and application regressions passed for those
boundaries. The complete `cargo xtask check --locked --offline` subsequently
passed on this source state (177 QML passes, seven gated skips, all 20 native
archive journeys, native cookie probes and workspace Rust suites). Strict
workspace Clippy, formatting and pack integrity checks also passed. The
slice's changed-layout, duplicate-identity, changed-route, nested-scroller
and timeout cases are covered by the native QML and focused application tests;
the live journey proves one useful committed restore. Changed targets remain
skipped/partial, stored scan IDs are never selector authority, and keyboard
scroll policy remains auto. Broader live-site and multi-page qualification is
separate from this slice. Production capture/viewing gates remain disabled.
