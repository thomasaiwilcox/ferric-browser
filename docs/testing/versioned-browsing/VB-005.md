## Native observations

In the original VB-005 run, `versioning_cookie_probe.qml` created a real WebEngine view to initialize a separate off-the-record profile from a synthetic `data:` URL. The C++ probe connected `QWebEngineCookieStore::cookieAdded` and `cookieRemoved` before setting synthetic cookies. It observed five fixtures: origin-host versus domain scope, the same name at a second path, persistent expiry, and Secure/HttpOnly/SameSite input. Domain/path/expiry/Secure/HttpOnly were exposed. A `QNetworkCookie` carrying `SameSite=Strict` before `setCookie` came back in `cookieAdded` as `Default` on both offscreen and native Wayland. This is a measured round-trip gap, not an inference about every source of Chromium cookies. [VB-073](VB-073.md) subsequently extended this same probe with a loopback request-scope check and Lax/None measurements; the original VB-005 test claim is unchanged.

`QNetworkCookie::parseCookies` accepted synthetic `Partitioned` and plain headers but returned the same public identifier; `toRawForm()` did not include the partition attribute. The public type has no partition-key accessor. This is representation evidence only: the probe did not create or inspect a real partitioned Chromium cookie. It intentionally does not collapse observations into a potentially lossy map.

`loadAllCookies()` is asynchronous and the public `QWebEngineCookieStore` signal set has only `cookieAdded` and `cookieRemoved`, not an enumeration-finished signal or consistency token. A rescan had zero further events in the probe's 250-ms diagnostic interval; the interval is not a proof of an empty or complete jar. The probe asserts `Unknown` for zero observations without completion and for identity-colliding observations. The strict general snapshot and merge gates remain unsupported. General seed/read-back is now unsupported for this backend because the tested SameSite attribute did not survive a native write/observe round-trip.

The detailed attribute/guarantee matrix is in [cookie-api-gap.md](cookie-api-gap.md). The [public Qt store documentation](https://doc.qt.io/qt-6/qwebenginecookiestore.html) confirms asynchronous operations, `loadAllCookies`-to-`cookieAdded` behavior and the domain/origin conversion rule; [QNetworkCookie's public members](https://doc.qt.io/qt-6/qnetworkcookie.html) define the available fields. The installed headers and native behavior were checked separately. No debugging-only cookie inspector was used; there is no debugger-derived claim.
