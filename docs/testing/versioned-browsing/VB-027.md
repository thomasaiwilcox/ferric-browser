# VB-027 — Allowlisted configuration capture and explicit policy restore

Status: verified for the VB-027 allowlisted policy transaction; VB-024 and broader native restore qualification remain separate open work.
Baseline SHA: `deea458d92bcf6d8fbea7b04af17823b5882cc1b`
Implementation SHA: uncommitted working tree.
Affected requirements and invariants: VERSION-001; VB-I04, VB-I12, VB-I14, VB-I18.

## Behavior implemented

The current schema captures one declarative allowlisted value, `content.javascript`, under a fixed schema fingerprint. Restore preview is profile-owner-bound, read-only, and displays only the current and captured boolean values. Applying requires an exact pending preview and explicit confirmation, and rechecks preview age, native/profile owner, configuration revision, current value, schema fingerprint, and the setting registry's type/sensitivity/apply-time/prerequisite metadata. The setting is applied through normal configuration validation; the preview is consumed once.

Policy-preview cancellation now also requires the originating window. A
different window cannot consume its request ID or dismiss the pending preview.
An authored regression checks cross-window cancellation immediately before the
valid owner confirms the same preview; it passed in the 2026-10-02 application
suite.

Ordinary structural restore planning does not apply policy. Unknown manifest fields and obsolete policy schema fingerprints fail closed. Permission grants, trust exceptions, external paths, credentials, security policy, and whole configuration documents are not captured or replayed.

## 2026-10-02 disposable native policy continuation

A fresh normal profile under `/tmp/ferric-vb027-native-Ll3fqd/profile` ran
against Qt 6.11.2 in a nested Weston headless compositor. The source window
set `content.javascript=false` through the normal command path and wrote one
durable structural commit. It then set the current value to `true`. Running
`restore <commit> --policies` showed the production Versioning panel's exact
allowlisted diff, `Current: enabled · Captured: disabled`; a read-only config
query still returned `true` before consent. The process-local Qt accessibility
switch exposed one exact Ferric application on AT-SPI. Pressing the panel's
visible `Apply the displayed policy setting and continue restore` action
within its 60-second preview lifetime changed the queried value to `false`
with source `temporary` and advanced the configuration sequence once. The
same process's live registry then contained the original window and a new
same-profile restore window; the original window and tab remained present.

The first nested compositor used Weston's kiosk shell and crashed in
`kiosk-shell.so` while the disposable browser was being restarted for
accessibility. `coredumpctl` identified Weston, not Ferric, as the faulting
process; no OOM was reported. Retesting under the standard Weston desktop
shell succeeded. A policy action attempted after the preview had aged out
left the config unchanged, consistent with the 60-second bound, but this
exploratory run did not capture a structured native refusal reason and is
not counted as a negative acceptance test. The final immediate action above
is the positive native evidence. Both final test processes exited after exact
SIGTERM and the disposable profile was retained for inspection; no user
profile or external account was touched.

This qualifies one allowlisted policy-apply and new-window UI journey. It
does not qualify native stale-revision/cancel paths, arbitrary settings,
ordinary restore's no-policy behavior, current-window replacement, or the
full VB-024 dependency.

The new application regression
`ordinary_restore_preserves_current_policy_and_permissions` now exercises the normal
pristine-window restore path with a manifest carrying captured JavaScript
policy `true` while current policy is `false`. After the structural pages are
applied, the current value remains `false`, the configuration revision is
unchanged, and an existing durable notification grant remains the same
record. Its focused test passed ten successive runs; the application versioning suite passed
131/131, strict application Clippy and workspace formatting checks passed.
This establishes the no-implicit-policy or permission-replay rule for the
application path; a native ordinary-restore non-mutation journey remains open.
The complete `cargo xtask check --locked --offline` passed on this source
state, including 166 passing QML tests, native bounded probes and the workspace
Rust suite. Together with the explicit preview/confirmation and stale-revision,
obsolete-schema and unknown-field regressions, this satisfies VB-027's stated
acceptance criterion: one allowlisted, validated Ferric policy transaction,
not whole-configuration replacement.

## Remaining limits

The allowlist is intentionally narrow and does not imply that restoring arbitrary application/security policy is supported. This slice does not qualify page capture, the full VB-024 new-window/current-window restore paths, or live replacement; those remain separately gated. Native negative paths should still be exercised in the final campaign, but they are not evidence for arbitrary policy support.
