## Native observations

`tests/native/versioning_archive_probe.qml` uses real QML `WebEngineView.save(path, MimeHtmlSaveFormat)` with two distinct off-the-record profiles. Its C++ harness owns a `QTemporaryDir`, a synthetic local HTML fixture and a loopback listener. The save produced nonempty MHTML. The source profile exposed exactly one `isSavePageDownload` request with the originating QML view, exact preauthorised directory/name and MHTML format; `downloadFinished` reported `DownloadCompleted`. A separate ordinary `data:` download arrived with `isSavePageDownload == false` and completed through its ordinary route. The QML save request required no `accept()` call; the ordinary download did. The probe's success predicate requires one correlated request, exact path/view/format, `DownloadCompleted` and nonempty output. It rejects `DownloadCancelled`, `DownloadInterrupted` and two matching candidates even if all other fields match.

Cancelling a second save in `downloadRequested` exposed `DownloadCancelled` on that request. Its `downloadFinished` signal arrived later; request-ID matching prevented that late event from being assigned to another save. Saving to a missing parent directory emitted a page-save request, remained `DownloadInProgress` through the one-second observation window, and produced no file. The probe cancelled it. This is not a successful capture or proof that Qt always emits `DownloadInterrupted`; a production job needs its own deadline, cancellation and cleanup verification.

The completed MHTML reopened in a fresh, separate off-the-record archive profile and rendered its original title. That profile was configured before navigation with JavaScript, local-to-remote access and local-to-file access disabled and a public `QWebEngineUrlRequestInterceptor` attached. A valid hostile MHTML was derived from the generated fixture and contained a remote CSS import, image, frame, meta redirect, form and popup script. It rendered its hostile title, caused zero loopback connections and no download or popup request. The view rejected a separate explicit external navigation before traffic. A diagnostic-only allowance for one localhost navigation reached the profile interceptor, which blocked it; the listener still saw zero connections. The allowance was then removed.

The MHTML form was present but synthetic mouse activation did not produce a form-navigation event on either offscreen Qt or native Wayland. Therefore this probe does **not** qualify the full archive interaction boundary or form submission handling. The archive profile/view policy here is a test fixture, not wired into Ferric's production archive surface. No archive-viewing command is enabled. The offline primitive remains unqualified until a deterministic user-activation/form/redirect/popup suite and production wiring pass. The capture primitive is supported only for the observed controlled-path public API; it does not qualify permit orchestration or durable publication.

## Privacy and scope

All pages, download payloads and MHTML are synthetic and live only in the temporary operation directory, which is removed on exit. The only server binds a random loopback port and records connection counts, not request content. No normal profile, account, credential, external host or private Qt API is used. The QML archive profile has no Ferric page bridge or userscripts. This probe does not authorise a production save or archive surface.
