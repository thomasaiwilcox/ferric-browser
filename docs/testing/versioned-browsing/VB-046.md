## Behaviour

Core defines a schema-1 `PageStateSidecar` for untrusted semantic-page results. `parse_json` rejects inputs over 256 KiB before parsing, checks the schema before full decoding, denies unknown fields, and validates explicit limits on same-origin frames, candidate identities, numeric positions, control state, sensitive editable values, category coverage and exclusions. Frame parent cycles, missing references, duplicate candidates, invalid HTTP(S) origins, non-finite or excessive coordinates, invalid fingerprints and oversized editable text fail closed. Coverage cannot claim more captured items than the corresponding records contain. The manifest's sidecar-object size limit uses the same core constant.

Candidate descriptors are hints, not native authority. A caller must independently match the top origin, route fingerprint, capture fingerprint and 128-bit request nonce through `qualifies_for`; there is no mutating or replay API here. The type has no public `Deserialize` or `Serialize` implementation, so the checked parser is its only constructor and the complete private-value structure cannot be sent through normal JSON projection. The `Debug` implementation and serializable `SidecarSummary` expose only bounded category/count/coverage/exclusion metadata, not editable values, origins, route fingerprints or candidate hints. This slice adds no collector script, storage write, UI restore, IPC command, or production enablement.

## Remaining boundary

The later collector must run reviewed code in ApplicationWorld, make its own traversal/time limits, and compare this DTO with its independently admitted request and document owner. Rust validation cannot certify that a malicious page/helper truthfully described a DOM element. Later storage/publication and restore slices must preserve the sensitive-value separation and never treat a candidate match as permission to submit, focus, or choose a keyboard scroll owner.
