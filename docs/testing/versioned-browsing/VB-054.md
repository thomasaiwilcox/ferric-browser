# VB-054 — Implement editable draft recovery and guarded refill

Status: verified for bounded editable-draft review and guarded refill; broader
site and release qualification remain gated.

## Implemented surface

- Editable draft recovery is a separate, unchecked-by-default option on the
  live-page reopen flow. The restore window gets only a bounded native preview
  for the exact owned destination tab after that option was selected.
- A modal native review dialog presents saved text as `Text.PlainText`, without
  selectors or identifiers. It is bounded to 64 entries and 16 KiB, reports
  omitted values, and has a 60-second safe timeout. Skipping, malformed or
  unavailable preview data, and timeout all continue structural restoration
  without editable refill.
- Bounded `contenteditable` text is included in that local dialog as a
  selectable text-only draft, explicitly labeled as display-only. It is never
  converted into a live refill target, even when the user separately approves
  native control refill. If the preview contains only display-only drafts, the
  confirmation action says “Continue without refill” rather than implying a
  live-page mutation.
- The dialog requires a second, explicit confirmation before the application
  can include editable values in its one-use page observation and restore
  plan. Refill targets are restricted to uniquely matched, visible, native
  text/search inputs, textareas, and positive checkbox values whose current
  values are blank/unchecked. Ambiguous, changed, sensitive, unsupported,
  contenteditable, radio, and nonblank live fields are skipped.
- The ApplicationWorld helper rechecks the live document and field, then makes
  a single property assignment. It does not focus controls, inject HTML,
  synthesize input/change/submit events, click, submit, or retry. Its result
  reports applied/skipped counts and the UI reports partial completion.
- Stored draft values are omitted from ordinary sidecar projections and Debug
  output. The temporary native preview is cleared after choice, timeout, or
  approved window close; an approved close also discards any not-yet-consumed
  native restore sidecar and stops outstanding restore callbacks. Every
  terminal geometry/refill attempt now discards the application-held sidecar
  immediately, including stale asynchronous callbacks and rejected plans.

## Focused tests

- Core cases cover opt-in, unique identity/context, current blankness, and
  limits for native text and checkbox targets. A separate preview case asserts
  that only bounded plain values leave Rust, frame exclusions are counted,
  and values/identifiers stay out of Debug and preview identity fields.
- A synthetic Qt WebEngine case covers one-time assignment to a blank input
  and unchecked checkbox, refusal to replace a nonblank value, readback of a
  page-refused assignment, and zero synthetic input/change/focus/blur/submit
  events.
- A negative QML case covers two blank fields with a shared name fingerprint:
  restoring a draft to either candidate must skip the ambiguous match and
  leave both values blank, even if their other descriptors differ.
- A core regression verifies contenteditable is available to the plain-text
  preview but excluded from refill planning; a QML fixture verifies that its
  typed value reaches the preview model, is rendered by a selectable
  `Text.PlainText` item, and uses the “Continue without refill” action. The UI
  labels the draft as nonrefillable. The focused core and QML checks passed
  in the complete project campaign recorded below.
- Formatting, strict workspace Clippy, the complete project check and the
  native committed-draft journey passed on the final source.

## Remaining qualification

- Immediate native-property readback identifies rejected assignments, while a
  site may later overwrite a value through its own framework lifecycle. The
  helper does not retry or claim application-level form acceptance; the user
  sees applied/skipped counts and the review dialog warns that the site may
  replace values.
- Keep page archive and editable recovery release gates closed until VB-057
  qualification. Broader site and account-state behavior remains outside the
  bounded fixture evidence.

## Native committed-draft-to-refill continuation — 2026-10-03

A disposable production-window journey now captures a synthetic unsaved text
draft in a local page through fixed one-use consent, the real frame-tree
collector, Qt MHTML save, the object worker and one durable commit. A fresh
browser window reopens that exact commit with editable recovery separately
opted in. The destination's input is observed blank while the native draft
review is visible and reports exactly one refillable value; the captured
contenteditable text remains display-only. After one explicit review
confirmation, the guarded ApplicationWorld assignment fills the blank input.
The fixture's `input`, `change`, `focus` and `blur` counters stay zero, and its
blur-triggered autosave handler is not invoked. Normal destination shutdown
then completes. The source and destination use the same synthetic route; the
stored draft is not emitted in test output.

The original editor fixture is separate, preserving its one-draft baseline.
The complete `cargo xtask check --locked --offline` passed on the final source:
177 QML passes, seven gated skips, all 22 native archive journeys, capability
probes and workspace Rust suites. Focused tests already cover a controlled
setter that refuses assignment, nonblank and duplicate-name matches, changed
route/origin refusal, contenteditable display-only recovery, and no synthetic
form events. The native journey establishes one ordinary text-input refill,
not acceptance by arbitrary SPAs, account-level site state, or long-term
survival against a site's later overwrite. Production archive/recovery gates
stay disabled pending VB-057; the forced runtime-QML compilation crash remains
a separate unresolved startup path.
