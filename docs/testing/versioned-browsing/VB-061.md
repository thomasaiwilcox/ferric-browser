# VB-061 — Visible-parent window-scope clean branch

Status: in progress. The application-side group transaction and native tab-capable child host are implemented behind `unqualified-clean-branch-test`; production clean branching remains disabled pending first-view replacement, compositor-focus and broader lifecycle journeys. Native mixed-group failure/reorder, partial view-allocation failure/retry, popup and permission journeys now pass in a disposable Qt test.

`BrowserApplication::plan_clean_branch_window` validates an already prepared window-scope structural manifest against the exact normal-profile native owner, application revision and current ordered live tabs. It maps each source tab to its logical page and safe-GET-or-placeholder navigation descriptor, checks the selected logical page, and refuses wrong profile UUIDs, reordered or stale pages, an unproved replayable URL, and scopes outside the 128-page bound. The plan is metadata, not a native lease or permission to navigate. The parent remains visible and active.

`begin_clean_branch_window_fork` reserves one child lease and submits one durable window-scope structural capture. At its completion, source owner, ordered tabs, selected tab, logical pages, target generations and safe-GET proofs are rechecked; a mutation aborts the lease even if the commit itself is durable. Only then is an ordered `WindowDurable` plan emitted. `publish_clean_branch_window_lineage` binds all child pages to the single child profile and branch record, but requires an exact matching child window, tab order, selected tab and live ephemeral owner. The single-tab publisher refuses group forks. The test-feature Qt route now carries the bounded plan to a hidden tab-capable child, creates one ordered native view per child tab in one off-record profile, checks every view's tab ID/UI/profile/interceptor/creation host, publishes lineage and only then admits proved safe GETs. The selected proved GET starts immediately; background proved GETs wait one-use for their tab to become active. Placeholders remain blank; the parent stays visible.

Evidence on 2026-10-07: `cargo test -p ferric-browser-application --features unqualified-clean-branch-test --locked --offline versioning::branch::tests --quiet` passed 15/15. The 128-tab plan regression verified source order and selected index 127, safe placeholders, and refusal of reversed order, wrong profile UUID, forged safe GET and a closed source tab. A durable three-tab transaction and ordered child-lineage test passed; reversed child order and single-tab publication were refused. Another test changed the source window before the durability callback and observed lease cancellation. The ordinary single-tab branch tests remain green.

The Qt adapter `cargo check -p ferric-browser-engine-qt --locked --offline --quiet` passed after the event-path change. `cargo fmt --all -- --check`, `git diff --check` and the pack validator passed; the adapter and application emitted existing unused-code/import warnings only.

Remaining qualification: native failed-allocation cleanup, first-view replacement/reorder refusal, broader close/restart privacy and compositor focus. A three-page native mixed outcome/reorder journey now joins the failed-URL/confirmed-close, popup/permission confinement, background-tab selection and first-view close-attempt evidence; these do not cover the remaining guarantees. No production gate is enabled.

Native-host preparation: `FerricBrowserWindow` retains its single-tab extra-view registry, while the new tab-capable host supplies the real window group. The shared branch popup ownership helper allows a listed extra view only if the published first-view lease remains exact and the extra view has the same child UI, off-record profile, native creation host and request interceptor. Its QML fixture passed 9/9, including forged and stale extra-view refusal.
