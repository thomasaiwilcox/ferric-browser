## Behaviour

`CookieObservationMirror` is application-owned, non-serializable and bound to one exact `NativeProfileOwner` and observation epoch. It requires consecutive local sequence numbers, retaining at most 256 current records. The conservative cap is below the core's 16 MiB material bound even if every individually validated record reaches its maximum permitted field sizes. It validates added records and removed identities against the backend version, scope and supported-attribute contract before retaining or applying them. Conversion failures must arrive explicitly as invalid events; overflow, sequence gaps/reordering, owner or epoch replacement, ambiguous identity collisions, invalid records, malformed removals and capacity exhaustion invalidate the epoch and clear retained records. A replacement profile requires a fresh mirror.

The source tag distinguishes a known requested rescan from an indeterminate callback, but neither implies mutation intent. Identical duplicate additions are idempotent. A changed value at the same key without an intervening observed removal is conservatively treated as a possible identity collision, because the public Qt key omits partition identity. A removal only removes a present diagnostic record; it never creates an absence observation, tombstone or branch delta. A removal followed by an addition yields only the new current record. Quiet intervals and an empty map remain unknown coverage. `diagnostic_read` returns observed-only, lossy, unknown-completeness data with no asserted change; even a synthetic qualified capability cannot promote this mirror to exact T0.

No Rust bridge from the C++ adapter is claimed in this slice. The mirror consumes already converted typed facts outside the native callback; any future bridge must pass conversion failures, queue overflow and exact profile/epoch/sequence data rather than silently dropping them. The public Qt adapter still cannot determine enumeration completion or distinguish rescan callbacks from live mutation callbacks.

## Privacy and ownership review

Only fixed synthetic test values were used. Mirror and event `Debug` omit cookie bytes; neither is serializable or persisted. Invalidation clears the retained map, and ordinary read projection remains count/handle only. Dropping the mirror destroys its owned Rust records; this makes no claim to erase transient Rust clones, Qt/Chromium copies, allocator memory, swap or crash dumps. No normal user profile, external account, private Qt API or Chromium database was accessed.

## Remaining boundary

The mirror is a diagnostic state holder, not a native-integrated complete snapshot, branch seed, mutation journal or merge writer. VB-073 owns conversion/fidelity qualification; VB-079 owns the backend decision. Existing production capability flags remain false.
