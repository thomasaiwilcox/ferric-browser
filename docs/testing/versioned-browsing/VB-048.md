## Behavior or investigation

- Added separately default-off QML choices for visible editable draft values and current selection positions. Both remain disabled behind the archive release gate.
- The Rust consent preview distinguishes archive-only, editable, selection, and editable-plus-selection requests. Fixed copy names editable-secret risk and states that selected text is not stored. The resulting non-serializable `PageCaptureAuthorization` retains both exact options.
- The reviewed ApplicationWorld page-state collector now accepts closed `include_editable` and `include_selection` booleans. It captures only visible text/search inputs, textareas, checkbox/radio checked state, and contenteditable text under one-use editable consent. Selection records only bounded start/end positions for a qualified active control; it does not return the selected text.
- The helper is now version `ferric-page-state-4`; its bounded traversal includes publicly accessible open Shadow DOM roots and extends hashed candidate context through each shadow host. The [DOM Standard's `Element.shadowRoot` contract](https://dom.spec.whatwg.org/#dom-element-shadowroot) returns `null` for both absent and closed roots, so a registered custom element without an exposed open root receives a fixed `uninspectable-component` exclusion and editable/selection coverage becomes partial. Closed-root content is never claimed as captured. The separately consented media metadata category is tracked under VB-055 rather than being folded into editable or selection values.
- For contenteditable selection, the helper now derives ordered absolute UTF-16 text offsets across bounded text nodes instead of storing node-local anchor/focus offsets. The selected text and text-node path are not returned; unsupported endpoints and traversal/time limits are reported as exclusions.
- Password, file, hidden, and metadata-marked token/session/OTP/credential controls are omitted with categorical exclusions. Metadata exceeding the 256-character inspection bound now fails closed as `sensitive-control` instead of being silently ignored; unreadable or non-string metadata fails closed too. Values are byte-bounded per value and in aggregate; DOM traversal, candidate count, value count, exclusions and elapsed time remain bounded. Default requests contain no editable/selection category or values.
- Bounded `contenteditable` text can be surfaced only through the local native
  recovery preview as plain text; the restore planner never treats it as a
  property-refill target or reinserts captured markup.
- Sidecar output remains an untrusted bounded DTO with redacted Debug and Rust admission. Test output uses synthetic values only; the `xtask` probe consumes and validates the result without printing it on success or failure.

## Privacy and ownership review

- The script request carries categories and bounds only; it receives no native path, profile handle, cookie, command or persistent authority. The values are intentionally returned only when the separate editable option is true and accepted through Rust one-use consent.
- Sensitive names and identifiers are hashed before sidecar output. Exclusion output contains fixed categories only. Editable values have no unredacted Debug/ordinary projection path.
- Heuristics reduce exposure but do not prove arbitrary text secret-free. The archive and editable draft remain sensitive and unsanitized; the feature remains disabled in production.
- Media source identifiers, when present, are represented only by one-way fingerprints; no source URL is added to the sidecar projection.
