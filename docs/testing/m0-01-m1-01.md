# M0-01 / M1-01 implementation evidence

Date: 2026-09-19  
Status: in-progress (core foundation and typed tab lifecycle added)

## Task card

- Requirements: BUILD-001, BUILD-003, ARCH-005, STATE-001, STATE-002,
  STATE-003, STATE-004, STATE-008, STATE-010, CMD-001, CMD-002, CMD-004, INPUT-001,
  INPUT-004, INPUT-005.
- Files: workspace manifest, `rust-toolchain.toml`, `crates/browser-core`,
  `crates/xtask`, and ADR-0001.
- Observable result: a Qt-independent reducer can create profiles, windows and
  tabs, capture a generation/document target, reject stale engine results,
  preserve ownership invariants, and emit typed effects. Runtime identity types
  now cover contexts, actions, requests, downloads, sessions, and journey nodes;
  tab existence, loading, renderer, and resource lifecycle are independent
  enums. Tab teardown is two-phase: `CloseTab` marks a live tab closing and
  freezes resources, then `ViewClosed` removes it only after the engine-side
  view has gone away; captured callbacks during that gap are diagnosed as
  stale. Same-profile tab movement preserves the captured target and emits a
  typed `ReparentView` engine effect; cross-profile movement is refused. A
  complete command
  chain can be parsed without execution, with quote/escape handling, limits,
  source-specific leading-colon rules, and registry metadata.
- Exit criteria: locked build, formatting check, core unit tests, and `cargo
  xtask check` pass.

The workspace uses `panic = "abort"` for both development and release
profiles. CXX-Qt-generated invokables are `noexcept`, so an application panic
must not unwind across the Rust/Qt boundary; the process-lifetime crash marker
remains present and is reported on the next startup instead.

User-facing command and configuration documentation is generated from the
typed command registry and configuration metadata with `cargo xtask docs`.
The generated `docs/user/commands.md`, `docs/user/configuration.md`,
`docs/user/bindings.md`, and `docs/user/actions.md` files are included in the
primary package and release artifact manifest. `cargo xtask check` rejects
stale generated output.

The repeatable Qt adapter smoke is `cargo xtask test adapter`; it uses a
disposable profile and the offscreen QPA for a bounded event-loop run. Real
Wayland, native input, popup, callback, and teardown qualification remain
separate.

## Validation

The repeatable core-only entry point is `cargo xtask test core`; it runs without
Qt, a display, or network access. The full workspace gate
`cargo xtask check --locked --offline` passed on 2026-09-19, covering 35
configuration, 76 core, 218 Qt adapter, 12 IPC, 65 storage, 77 CLI, and 12
xtask tests, with all doc-tests passing. Workspace Clippy also passes with
warnings denied; the only build output is the known Qt `QChar` SFINAE warning
from generated/native headers. The three-run core/storage repeat smoke, fixture tests,
accessibility contract, compatibility-report structure check, and
`cargo xtask check --locked --offline` also passed.

On 2026-09-19, `cargo xtask test wayland` passed on the current host now that
`weston` is available. The bounded run qualifies native startup, fixture-backed
navigation, and child/runtime cleanup only. Interactive focus, portal
interaction, CXX-Qt bridge qualification, and real engine callbacks remain
later work items; durable profile/session UUID storage is implemented at the
storage boundary but is not a substitute for those runtime qualifications.
