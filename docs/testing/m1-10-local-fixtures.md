# M1-10 local web fixture server evidence

Date: 2026-09-19  
Status: in-progress

## Scope

`cargo xtask fixture-server` runs a bounded, deterministic fixture server on
loopback. It binds an ephemeral port by default and prints one
machine-readable `RUSTBROWSER_FIXTURE_READY` line. The server handles one
request at a time and accepts only bounded HTTP/1.1 headers and bodies.

Pass `--https` to wrap the same routes in an ephemeral, one-day, loopback-only
certificate generated by OpenSSL and a local `socat` TLS proxy. This mode is
development-only and deliberately requires explicit test-side certificate
handling (for example, `curl --insecure`); it does not change RustBrowser's
production certificate policy.

The certificate covers both `127.0.0.1` and `localhost`. Those hostnames are
distinct origins even when they use the same loopback port; `/cross-origin`
provides a bounded link to the `localhost` alias for origin-boundary tests.

The fixture routes cover the first navigation regression slice:

- `/redirect` → `/final?from=redirect` with HTTP 302;
- `/post` → `/post-result` with a form and HTTP 303 after submission;
- `/post-307` → `/post-307-result` with HTTP 307 method-preserving behavior;
- download, Basic-auth challenge, popup, geolocation, and not-found routes;
- multipart file-form and editable-form pages;
- same-origin iframe and open shadow-root pages;
- a service-worker registration/script pair;
- a bounded synthetic heavy page;
- a WebSocket upgrade endpoint that validates the RFC handshake and echoes one
  bounded fixture frame.

The production browser still owns TLS validation and does not trust a fixture
certificate. The nested native Wayland smoke now starts the loopback fixture
server and opens `/editable` in RustBrowser for its bounded lifetime. This
proves fixture-backed launch and teardown, but not interactive form editing,
cross-origin HTTPS coverage, or portal behavior; no production TLS exception
is introduced by this server.

## Verification

```text
cargo xtask test fixtures
cargo test -p xtask --locked --offline
cargo clippy -p xtask --all-targets --locked --offline -- -D warnings
cargo xtask fixture-server --bind 127.0.0.1:0 --once
cargo xtask fixture-server --https --bind 127.0.0.1:0 --once
cargo xtask test wayland
curl --silent --show-error --dump-header - http://127.0.0.1:<PORT>/redirect
curl --silent --show-error --insecure https://127.0.0.1:<HTTPS_PORT>/frames
curl --silent --show-error --insecure https://127.0.0.1:<HTTPS_PORT>/cross-origin
```

The live loopback probe returned HTTP 302 with the expected relative
`Location` and bounded body. Route tests assert the 303 and 307 POST semantics,
the standard WebSocket acceptance value, bounded browser-behavior routes, and
reject empty/unknown routes.
