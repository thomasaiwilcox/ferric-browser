# ADR-0019 — Refined browser surface language

Status: accepted (2026-10-15), under the owner's product-polish direction.

Everyday browser surfaces present the outcome, relevant scope and available
actions before implementation details. Canonical command names and
configuration keys remain useful power-user affordances. Internal event names,
record IDs, serialized state and engine error codes are inspection details,
rather than the primary explanation.

Command-backed surfaces keep their real command header. Prompts generated by a
page, authentication request or browser lifecycle event use a plain context
label instead of implying that an internal event name is an invokable command.
Both retain the shared modal input, safe-choice and dismissal contract.

Friendly labels are presentation only. Commands, action identifiers, registry
values, target identities, security decisions and diagnostic/export formats
retain their existing contracts. Page-provided and user-provided content is
rendered literally. Optional details stay selectable when useful for support.

The [polish implementation record](../implementation/product-polish-2026-10-15.md)
tracks the broader audit and qualification; this decision does not claim the
entire experience has already been polished or qualified.
