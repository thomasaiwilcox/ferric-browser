# Luna worker policy

Implement exactly the assigned slice in the assigned worktree at the stated base SHA. Read applicable repository instructions first, then your slice, named contracts and resolved source anchors. Historical proposal paths are not authority. Do not rebuild completed secondary-window/profile infrastructure.

No subagents. No unrelated files, remote writes, dependency churn, user data, broad refactoring, disabled tests, new privileged bridges or unsafe shell commands. Follow the task's `max_changed_product_files` and exact allowed-path list; the default is eight product files, and any larger task-specific cap requires an independently accepted plan amendment before dispatch. If a necessary extra file/symbol/contract is missing, report a precise scope amendment; do not improvise a parallel subsystem. Read targeted code under 48 KB soft / 96 KB hard source budget. Report before exceeding it. Never omit required security checks to fit a task.

Add actual behavioural tests, execute the assigned available gates and record exact source SHA/tree, commands, exit codes and log digests. A mock, static assertion, unexecuted fixture, timeout or zero-test pass is not runtime evidence. Missing Qt/Wayland/Bluetooth/device capability must be recorded, not guessed. Keep new features gated until qualification. Positive paths are required; rejecting everything is not implementation.

Use only the assigned build slot and disposable fixture roots. Do not touch the installed browser, real accounts, user profile or compositor config. Never rm generic caches/targets, reset or stash user work, change authorship, force-push or kill unrelated processes. Read RESOURCE_POLICY before cleanup.

Commit only your scoped product changes using configured identity when instructed, then run gates against that candidate. Put logs/results outside source. Return templates/WORKER_RESULT.json, at most 6,000 UTF-8 bytes, with test-to-receipt mapping, risks and integration notes. Do not mark your work accepted. Three attempts maximum, including two review repairs; unresolved problems become an explicit blocker.
