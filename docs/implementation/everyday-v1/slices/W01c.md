# W01c — Keep destructive command effects within their explicit scopes

**Lane:** core · **Type:** implementation/verification · **Parent:** W01 · **Requirement:** EF-W01
**Dependencies (accepted, not just coded):** F01b, S00
**Exclusive lock:** command-dispatch
**Contracts:** C01, C09, C13

## Outcome

Qualify exact tab/window destructive scopes across the core dispatcher and Qt tab command route. Tab-close and pin operations must never widen to all group members or windows implicitly; quit remains the explicit global shutdown action. Preserve existing default commands and user custom bindings.

## Required reading and permitted changes

Edit only these two product paths:

- `crates/ferric-browser-core/src/dispatcher.rs`
- `crates/ferric-browser-engine-qt/src/browser_ui_tabs.rs`

Read the dispatcher reducers, command registry, `tab-pin` route, and tab/window action adapter before changing behavior. The existing reducer assertion does not prove that a `tab-pin` command targets the requested tab; add a behavior-backed assertion at the in-scope route or test seam. Do not change W03 window-host behavior.

## Acceptance

**T105 — Destructive scope (unit).** tab-close/pin/quit semantics never widen to all group members or all windows implicitly. Assertions must use distinct tabs and windows and inspect dispatched effects, including the actual `tab-pin` command target, not only reducer state or source strings.

Use the `application-rust` recipe in `TESTING.md`. Run the focused T105 assertion and affected core/Qt tab-command regressions on the exact source. Bind the existing T105 ID to executable assertions and a receipt; no zero-test or skipped-only result is accepted.

Return the standard worker result with exact candidate SHA, changed files, T105 evidence, limitations and integration notes. This child does not carry context routing work from W01b.
