**Parent:** P00 aggregate · **Lane:** security · **Type:** proof · **Requirement:** EF-P00

**Exclusive locks:** credential-boundary, test-registration · **Contracts:** C04, C14

## Outcome

Prove that the proposed Qt 6.11.2 WebEngine/WebChannel transport is isolated from ordinary page/script worlds, that native authority uses trusted main-frame and document facts rather than page claims, and that the authority is bound to the current document. This child owns T046.

## Scope

The worker may edit only the existing five paths listed in the plan: the credential boundary application test, its two hostile/frame fixtures, everyday CMake registration, and the credential-boundary ADR. Use no real authenticator material. Add no production WebChannel wiring, generic scheme/console fallback, or Chromium patch. Source-check all world IDs and preserve existing native WebAuthn behavior.

Exercise ordinary MainWorld/ApplicationWorld access and subframe reachability. Resolve compile/setup issues only within these five paths. The proof must use the actual public Qt API on the qualified Qt 6.11.2 build and run T046 with zero skips.

## Handoff

Preserve exact source/runtime evidence and obtain independent review before P00b starts. A passing channel-connectivity check alone is insufficient; evidence must show who supplies origin/context and which document owns the lease.
