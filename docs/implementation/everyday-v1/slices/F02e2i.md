# F02e2i — Expose typed live profile-session identity

**Requirement:** EF-F02 · **Amendment:** A53 · **Depends on:** accepted F02e1 and F02e2q.

The actual profile-session identity is a genuine prerequisite for the reserved F02e2s source attempt3. This task does not replay a failed native attempt or reset another task’s counter.

## Outcome

Add an opaque `ProfileInstanceId` whose construction remains internal to the application. It identifies one actual live `Arc<Session>`, independent of optional durable ProfileId/storage scope. The same shared/cloned live session returns the same value; independent memory sessions differ, including Private and Ephemeral profiles with identical labels. Durable owners with matching id and roots share one live identity through the existing weak registry. Different roots/IDs differ; once all actual owners die, a new session has a new identity. A copied ID cannot prolong a session or grants. Keep SessionScope, durable IDs, storage roots, privacy and permission/download behavior unchanged.

Expose `BrowserApplication::profile_instance_id() -> Option<ProfileInstanceId>`: None without an active profile, Some trusted live identity for Normal, Private and Ephemeral profiles. Re-export the opaque value as needed. Equality/hash/display are sufficient; no public constructor/parser/serde, raw SessionScope, session Arc, storage authority or persistence upgrade. An ID alone is not authorization.
