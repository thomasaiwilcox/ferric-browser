# F01c — Verify feature disable semantics after consumers land

**Lane:** qualification · **Type:** verification · **Requirement:** EF-F01
**Dependencies (accepted, not just coded):** F01b, H01, P12, S01
**Exclusive locks:** test-registration, native-build
**Contracts:** C01, C13

## Outcome and work order

1. Add assertions to the accepted H01 hot-preparation test proving that disabling `performance.hot_tab` invalidates queued preparation without changing live browsing.
2. Add assertions to the accepted P12 credential lifecycle test proving that disabling `passkeys.phone` cancels bridge-owned phone work while native authentication and unrelated browsing remain intact.
3. Run the production-backed tests on the exact integration source. Both positive transitions are required; changing a requested flag alone is not evidence of cancellation.

## Allowed product paths

- `crates/ferric-browser-engine-qt/tests/everyday/tst_hot_prepare.cpp`
- `crates/ferric-browser-engine-qt/tests/everyday/tst_credential_lifecycle.cpp`

These tests are created by H01 and P12. This verification slice may update only those two registered test files; do not edit implementation or disable either assertion.

## Acceptance case

**T012 — Disable semantics (application).** Disabling prewarm/auth invalidates corresponding work without changing unrelated browsing or native auth.

## Verification and handoff

Use the `baseline` recipe in `TESTING.md` after H01, P12 and the matched S01 native harness are accepted. Record each test method, fixture, exact integration SHA/tree, CTest output and run-gate receipt. If the exact Qt 6.11.2 SDK remains missing `Qt6WaylandCompositor`, leave T012 unqualified and report that blocker; do not substitute Qt 6.12 or a mock.
