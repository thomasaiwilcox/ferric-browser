# C07 — Network, privacy and authenticator semantics

The phone helper is a new egress path. Before launch, derive the actual effective proxy/restriction policy through existing Ferric application configuration. It must not silently bypass a configured proxy, offline mode, certificate trust or domain/relay restriction because its network stack differs. If the selected library cannot honor a policy, return a clear unavailable reason and do not connect directly. Do not assume HTTPS proxy environment variables also control WebSocket traffic; test connection destinations using an owned proxy fixture. Inspect library relay construction; page fields cannot choose arbitrary tunnel endpoints.

Use the conventional QR-initiated hybrid mode that actual target phones support. Bluetooth proximity and encrypted tunnel operation remain library responsibilities. Do not require newer direct-BLE transport or remembered pairing. A capability probe may inspect Bluetooth/PSL/helper availability with bounded operations; it must not register credentials, continuously scan, change adapter power or open a secret-bearing tunnel by itself. Missing BlueZ permissions are a capability error, not an invitation to use sudo.

No credential cache, pairing record, assertion, credential ID, user handle, challenge, signature, raw clientDataJSON or QR secret is written to profiles, command history, macros, logs or diagnostic exports. Pinned transient protocol data and error redaction must cover helper crashes and malformed output as well as successful requests. Memory zeroization should follow available library conventions; do not claim complete process-memory secrecy.

Private/ephemeral mode may perform explicitly approved phone authentication after the same gate passes, but pairing/credential metadata is never retained by Ferric. Explain in registration UI that a credential created on the phone persists there even when the private browser window is closed. Do not export a private site identity to a public group title or diagnostic.

Relying-party validation is browser-origin-bound and library-checked with maintained Public Suffix List data. Test IDNs, normalized default ports, public suffix rejection, parent domain versus unrelated sibling, malformed URL/opaque contexts and unsupported related-origin requests. Document that loopback allowances exist only in isolated test builds/fixtures and are not an insecure production toggle.

Existing native authentication remains usable when phone is off, blocked, unavailable or unqualified. Feature failure must not cancel unrelated Qt native requests. Request budgets and rate limits apply per exact page plus a process-wide bridge-managed ceremony admission; background request storms cannot steal keyboard focus or replace an existing prompt.
