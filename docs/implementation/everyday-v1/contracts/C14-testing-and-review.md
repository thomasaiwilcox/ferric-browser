# C14 — Test construction, independent review and cross-feature proof

Use three complementary layers: pure Rust policy/state tests; actual Qt/WebEngine/native actor tests; composed browser tests using production resource registration and routing. Add adversarial fixtures and native/physical qualification. Use existing application harness, disposable profiles and isolated portal/compositor fixtures. No ordinary test opens a personal account, changes the live desktop or registers a real credential without user action.

Each slice names positive, negative and regression cases in the test matrix. Bind every case to an actual test function/inventory and receipt. Production dependencies can be mocked at well-defined seams for deterministic races, but a separate composed positive path must execute real code. A test-only browser implementation doesn't qualify production. Keep all existing regressions including native search, hints, portal ownership, downloads, POST reload decisions and startup recovery.

New native/application suites use a separate `tests/everyday/` directory linked to the Cargo-built production engine, following current application CMake patterns. S01 registers this harness in the repository gate without replacing existing suites. Native variants must select the actual supported runner/backend and prove its input capability. `ctest --show-only=json-v1` and `--no-tests=error` (or supported equivalent) are mandatory. Existing CMake exposes FERRIC_ENGINE_LIBRARY; pass the explicit actual artifact path to avoid accidentally testing an old library.

Use an independent relying-party verifier/test server (prefer a pinned established library in an isolated test dependency environment); do not use the same helper's own validator as the sole oracle. Verify create+get cryptographically, with wrong-challenge/origin/RP/signature controls which must fail. Fixture credentials are disposable. Native provider success, not just cancellation, must also be tested.

Cross-feature cases: adopted hot page requests credentials; first visible host closes; tab/profile generation changes during all in-flight operations; concurrent opens/auth requests; grouped backgrounds; popup opener; real settings reload; private/normal same display names; missing helper/PSL/BlueZ/proxy/compositor; renderer failure; mixed-group manual regroup; session restoration interrupted; final shutdown with operations in flight.

Independent reviewer is a different agent/context and is not the author. It traces requirements to code and tests, checks wrong-target/race paths and rejects scope drift. Security proof gates get explicit senior/human review before general release; a second model review is useful but not a substitute for missing physical/security evidence. All subsequent code changes invalidate affected test receipts and qualification until rerun/reviewed.
