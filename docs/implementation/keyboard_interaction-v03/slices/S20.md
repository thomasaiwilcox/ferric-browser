## Implementation order
1. Build only an isolated public-adapter experiment for pointer-driven in-view drag, with both points chosen before press.
2. Prove press/move/release, capture, deactivation, prompt, Escape, destruction and watchdog cleanup; distinguish HTML drag/drop from pointer-driven widgets.
3. Record the exact categories supported, remaining site effects and public API limitations. Produce a machine-readable go/no_go decision and an ADR.
4. No-go means S21 is not_applicable; all independent core work can continue.

## Do not do
No production drag UI, OS injection, QML-clocked held pointer, cross-window/file drag, fake rollback or blind retry.
