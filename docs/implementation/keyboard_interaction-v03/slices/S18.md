## Implementation order
1. Extend existing binding-explain/Site Doctor with actual owner/rule/category/rejection facts and a local interaction-status view.
2. Use bounded on-demand plain-text/redacted output; exclude values, typed streams and private URL components. Exporting page-derived labels requires separate consent.
3. Provide disabled-by-default auditable data-profile examples only where settings are implemented; qualify any shipped site profile and document override/disable behaviour.
4. Update representative workflows as target journeys with actual evidence levels, not as blanket compatibility promises.

## Do not do
No second diagnostics subsystem, continuous keylogger, remote downloaded adapters, hostname conditionals in core or label persistence.
