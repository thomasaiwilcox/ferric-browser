# S22 research plan

## Question

Can a framework-specific editor adapter separate focus, extraction, bounded
apply, and framework commands while rejecting permission denial, a stale
revision, or a replaced editor instance without partial mutation?

The investigation uses pinned releases of Ace, CodeMirror 6, Monaco,
ProseMirror, Tiptap, and Quill. It adds no user-facing feature, production
adapter, page-content persistence, or generic `value`/`innerHTML` writeback.

## Probe

The standalone `tests/framework-probes` harness installs exact npm package
versions from its lockfile into a temporary directory. It serves a local
WebEngine fixture; the browser makes no CDN requests. Each live framework
instance is tested independently for its public focus and extraction APIs, a
consent-denied no-op, an external edit after capture, an editor-instance swap
at the same harness revision, a bounded replacement, selection retention,
format retention where the model supports rich marks, and framework undo.
The report contains booleans and package versions only; it never prints the
fixture document text.

The temporary browser bundle is generated by esbuild from the lockfile. No
bundle or `node_modules` directory is committed. The QML probe stays outside
the default offline engine test folder so ordinary `cargo xtask test engine`
does not acquire a JavaScript package-network dependency.

## Decision rule

The fixture can prove public API behavior for the pinned package build in this
local QtWebEngine. It cannot prove compatibility with an arbitrary site's
configuration, a collaboration provider, or installed native keyboard/IME
behavior. A cross-framework product writeback path is a no-go unless each
framework has an explicit target/revision adapter, its own consent scope, and
native qualification. Missing native input remains unavailable evidence, not
a technical failure.

## Evidence mapping

- T050 uses `python3 crates/ferric-browser-engine-qt/tests/framework-probes/run_probe.py`
  and records its WebEngine log.
- T018 uses the repository's native engine suite for generic editor entry,
  mode transitions, lost releases, and IME behavior. Those cases do not mount
  the pinned framework packages. Framework-specific native/IME qualification
  is recorded separately as not run.
- The native Wayland attempt is recorded independently; compositor startup
  alone is not keyboard evidence.
